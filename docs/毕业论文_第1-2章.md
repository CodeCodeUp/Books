# 基于协同过滤与内容特征的图书馆资源智能化推荐系统的设计与实现

---

## 第1章 绪论

### 1.1 研究背景与意义

#### 1.1.1 研究背景

随着图书资源数字化和在线服务的发展，图书系统已经从单纯的信息检索工具逐步演变为面向读者的综合知识服务平台。在图书数量持续增长的背景下，传统的关键词检索和分类浏览虽然仍然必要，但很难持续满足用户对个性化发现、快速筛选和连续阅读的需求。如何在海量图书中主动向用户推荐其可能感兴趣的内容，已经成为图书信息服务中的关键问题。

推荐系统为解决上述问题提供了可行路径。协同过滤能够从群体行为中挖掘偏好规律，基于内容的方法能够利用图书元数据和文本特征补足冷启动场景，而混合推荐则有助于在不同用户状态下平衡准确性、覆盖率与可用性。图书推荐场景又具有自身特点：显式评分稀疏、长尾图书数量大、用户兴趣差异明显、热门图书与冷门图书的数据质量差异较大，因此简单依赖固定权重或单一算法往往难以获得稳定效果。

本项目基于 Book-Crossing 数据集构建图书推荐系统，采用 Vue 3 前端、Spring Boot 后端与 Flask 算法服务协同工作的实现方式。当前系统已经实现用户协同过滤、物品协同过滤、TF-IDF 内容推荐，以及面向个人推荐页和图书详情页的动态混合策略，并结合用户评分历史、年龄和兴趣信息进行推荐路由与冷启动处理。因此，本研究既关注推荐算法本身，也关注推荐能力在实际 Web 系统中的落地过程。

#### 1.1.2 研究意义

本研究的意义主要体现在算法验证、系统落地和工程实践三个层面。

第一，在算法层面，本研究围绕高稀疏度图书数据场景，对用户协同过滤、物品协同过滤与 TF-IDF 内容推荐进行了实现和组合。系统并未采用脱离业务场景的固定权重混合，而是根据用户评分历史、兴趣、年龄以及目标图书的数据质量动态选择推荐路径。这说明在毕业设计和中小规模系统场景下，基于记忆的协同过滤与内容特征方法仍然具有较高的工程价值和研究价值。

第二，在系统层面，本研究并未停留在单一算法实验，而是将推荐能力嵌入完整业务流程中。系统已实现注册登录、资料完善、兴趣维护、图书浏览、图书评分、个性化推荐和相似图书推荐等功能，形成了“用户交互 - 数据写入 - 推荐刷新 - 结果展示”的业务闭环。这使得论文讨论对象不仅是算法模型，也包括推荐服务如何与业务系统协同工作。

第三，在工程层面，本研究积累了中等规模图书推荐系统的实现经验。当前系统处理 433,671 条有效评分、271,360 本图书和 77,805 名用户，采用候选预筛选、缓存、异步预计算、分页返回和失败降级等手段控制响应时间与资源消耗。这些做法对于类似规模的信息推荐应用具有直接参考价值。

因此，本研究的价值不在于提出完全全新的推荐理论，而在于基于当前可运行代码，给出一套面向图书场景、兼顾算法效果与系统可用性的实现方案。

### 1.2 国内外研究现状

#### 1.2.1 推荐系统研究综述

推荐系统已经形成较为成熟的技术谱系。协同过滤通过用户 - 物品交互数据挖掘偏好规律，是应用最广的方法之一；基于内容的推荐通过分析物品特征完成相似性匹配，适合处理用户行为不足的场景；混合推荐则通过组合多种算法弥补单一方法的不足。

从研究演进看，推荐算法已经从早期的记忆式方法逐步发展到矩阵分解、深度学习和图神经网络等更复杂的模型。但在很多实际系统中，是否采用复杂模型并不是唯一关键，数据质量、稀疏度、可解释性、服务延迟和部署复杂度同样会直接影响方案选择。对于毕业设计和中小规模业务系统而言，结构清晰、易于验证且可工程落地的方法依然具有研究价值。

当前推荐系统领域仍面临几个共性问题：一是显式反馈稀缺，评分矩阵高度稀疏；二是新用户和新物品的冷启动问题长期存在；三是准确性、多样性、实时性与可解释性之间往往存在权衡；四是许多论文工作停留在离线实验，缺少与实际业务流程的一体化验证。

#### 1.2.2 图书推荐系统研究现状

图书推荐是推荐系统的重要应用分支，也是数据稀疏问题较为典型的场景。公开数据集中，Book-Crossing 因规模较大、评分分布真实，被广泛用于图书推荐研究。围绕该类数据集，现有研究通常采用用户协同过滤、物品协同过滤、内容特征建模以及多种混合推荐方案，以改善冷启动和长尾推荐问题。

与电影、音乐等领域相比，图书推荐存在几个更突出的特点。首先，图书元数据相对丰富，书名、作者、出版社、出版年份等信息适合做内容建模；其次，用户显式评分比例较低，导致协同过滤在许多用户上难以直接发挥作用；再次，图书主题跨度大、生命周期长，热门书和冷门书的数据质量差异明显，因此推荐策略往往需要区分用户状态和图书状态。

已有图书推荐研究表明，单一算法通常难以覆盖全部场景：纯协同过滤在高活跃用户上效果较好，但对新用户和低活跃用户支持不足；纯内容推荐能够处理冷启动，但个性化深度有限；混合推荐能够提升整体可用性，但如果仍采用固定权重，往往难以适应不同数据质量下的推荐需求。基于这一认识，图书推荐系统越来越强调“按场景选择算法”，而不是“全局统一一套权重”。

#### 1.2.3 现有研究的局限性

结合现有研究与当前项目需求，可以将图书推荐领域的主要不足概括为以下四点。

第一，很多方案仍以固定权重混合为主，缺少按用户状态和图书状态动态调整策略的能力。当评分数据质量差异较大时，固定比例很难始终保持合理。

第二，部分冷启动方案依赖复杂的人口统计信息、外部知识库或人工标注标签，真实系统中往往难以稳定获得这些数据。相比之下，基于评分历史、基础年龄信息和用户主动选择兴趣的组合，更接近实际业务可采集的数据条件。

第三，不少研究更关注离线指标，而对缓存、增量更新、失败降级、接口交互等工程问题讨论不足。对于在线系统而言，推荐是否“能算出来”和“能稳定返回”同样重要。

第四，图书推荐论文中常见“算法描述强于系统实现”的问题，即理论上设计了完整混合框架，但实际系统只落地了部分流程，导致论文与代码无法互相印证。

基于上述不足，本研究选择从当前可运行系统出发，重点完成三类工作：一是实现适应高稀疏数据的协同过滤与内容推荐；二是实现面向不同用户状态、图书状态的动态路由与混合策略；三是将算法能力嵌入完整 Web 系统，并通过离线评估与功能验证说明其实际效果。

### 1.3 研究内容与目标

#### 1.3.1 研究目标

本研究的总体目标是基于当前可运行代码，设计并实现一个融合协同过滤与内容特征的图书推荐系统，使其既能够在高稀疏数据条件下提供可用推荐，也能够在 Web 业务流程中稳定落地。围绕这一总体目标，本文从算法、系统和验证三个层面展开。

算法层面目标包括以下三点。第一，实现适用于显式评分稀疏场景的用户协同过滤与物品协同过滤算法，分别服务于推荐页和图书详情页的主要推荐需求。第二，实现基于图书标题、作者、出版社等信息的 TF-IDF 内容推荐方法，并结合兴趣主题和年龄信息补足冷启动场景。第三，构建面向不同用户状态和图书状态的动态混合机制，避免使用固定比例对全部场景一刀切处理。

系统层面目标包括以下三点。第一，构建 Vue 3 前端、Spring Boot 后端与 Flask 算法服务协同工作的前后端分离架构。第二，实现注册自动登录、资料完善、兴趣维护、图书浏览、图书评分、个性化推荐与相似图书推荐等核心功能，形成完整的业务闭环。第三，建立评分后缓存清理、推荐预计算、分页返回与失败降级等工程机制，提升系统可用性与响应效率。

验证层面目标包括以下三点。第一，基于 Book-Crossing 数据集及导入后的系统数据验证算法在高稀疏场景下的适用性。第二，采用留存验证法和 Precision@10、Recall@10、F1-Score@10、Coverage 等指标，对已实现的核心推荐算法进行离线评估。第三，通过接口联调与页面功能验证，说明推荐能力在实际系统中的可调用性和完整性。

#### 1.3.2 研究内容

为实现上述目标，本文围绕以下六个方面开展工作。

**（1）数据整理与系统导入**

本文以公开的 Book-Crossing 数据集为基础，结合项目中的数据清洗与导入脚本，对图书、用户和评分数据进行整理，并导入系统数据库。处理重点包括显式评分筛选、图书元数据规范化、用户基础信息整理以及业务表初始化，使推荐算法和 Web 系统能够共享统一数据源。清洗与导入后的系统数据规模为 433,671 条有效评分、271,360 本图书和 77,805 名用户，能够体现图书推荐场景中典型的高稀疏特征。

**（2）协同过滤算法实现**

在个性化推荐场景中，本文实现了基于用户的协同过滤方法。该方法先依据共同评分图书筛选候选相似用户，再利用余弦相似度度量偏好接近程度，最后通过加权平均预测目标用户对未评分图书的潜在评分。在图书详情场景中，本文实现了基于物品的协同过滤方法，通过共同评分用户构建目标图书与候选图书的相似度，用于生成“相似图书”结果。两类协同过滤方法均采用候选预筛选与批量计算以降低开销。

**（3）内容推荐与冷启动处理**

本文实现了两类内容相关推荐逻辑。对于已有评分历史的用户，系统使用图书标题、作者和出版社构成文本语料，基于 TF-IDF 构建图书向量，并通过用户历史高权重图书形成用户内容画像，进而生成内容相似推荐。对于没有评分历史的用户，系统不再依赖复杂人口统计规则，而是采用“兴趣优先、年龄辅助、热门兜底”的冷启动路径：如果用户选择了兴趣主题，则优先推荐对应主题图书；如果只有年龄信息，则依据年龄偏好对图书年代和质量进行排序；如果两类信息都缺失，则返回高质量热门图书。

**（4）动态混合策略设计**

本文没有采用固定比例混合，而是根据不同场景动态确定协同过滤与内容推荐的组合方式。对于推荐页，系统依据相似用户数量和平均相似度计算协同过滤置信度，将协同过滤占比动态映射到 50% 至 90%，其余部分由内容推荐补足；当用户选择了兴趣主题时，还会对匹配兴趣主题的候选图书进行额外加权。对于图书详情页，系统依据目标图书的评分数量、物品协同过滤结果数量和平均相似度动态计算混合比例，使热门图书更依赖协同过滤，冷门图书更依赖内容特征；当两类算法都无法返回结果时，再降级到同作者图书推荐。

**（5）系统架构与业务流程实现**

本文将推荐能力嵌入完整的三层系统中。前端基于 Vue 3 实现首页、图书浏览、图书详情、推荐页、个人中心、评分历史和资料完善等页面；后端基于 Spring Boot 提供统一 REST 接口，负责用户认证、图书查询、评分写入和推荐服务调用；算法服务基于 Flask 独立部署，负责推荐计算、缓存管理与健康检查。系统支持注册后自动登录、年龄填写、兴趣选择、评分后清除缓存与异步预计算等业务流程，形成完整的推荐闭环。

**（6）离线评估与功能验证**

在验证层面，本文对已实现的核心算法进行留存验证式离线评估，并使用 Precision@10、Recall@10、F1-Score@10、Coverage 等指标分析其效果。同时，本文结合前后端接口联调和页面功能测试，验证用户注册、资料完善、图书评分、推荐生成与相似图书展示等关键流程是否能够稳定运行。这样可以同时从“算法有效”和“系统可用”两个维度评价项目成果。

## 第2章 相关技术与理论基础

### 2.1 推荐系统基础理论

#### 2.1.1 推荐系统概述

推荐系统是一种典型的信息过滤技术，其目标是在大量候选对象中识别出与用户偏好更匹配的内容，并以推荐列表的形式主动呈现给用户。在图书场景中，推荐系统要解决的核心问题不是“图书是否存在”，而是“在海量图书中哪些更值得优先展示给当前用户”。

从数据结构上看，推荐系统通常包含用户、物品和交互三类核心要素。用户是推荐结果的接收者；物品是被推荐的对象，本研究中对应图书；交互数据则反映用户对图书的偏好强弱，在本项目中主要体现为显式评分。若将所有用户对所有图书的评分组织成用户-图书矩阵，就可以将推荐问题形式化为对矩阵缺失项的估计，以及基于估计结果生成 Top-N 推荐列表的问题。

图书推荐具有明显的数据稀疏特征。用户通常只对极少数图书进行评分，而大多数图书只被少量用户接触，这使得推荐系统既要尽量利用已有交互数据，又要在数据不足时提供合理的冷启动方案。因此，推荐系统在图书场景中不仅是一个算法问题，也是一个兼顾准确性、可用性和工程可落地性的系统问题。

#### 2.1.2 推荐系统分类

按照推荐依据的不同，推荐系统通常可分为基于内容的推荐、协同过滤推荐和混合推荐三类。

第一类是基于内容的推荐。该类方法通过分析图书本身的特征，如标题、作者、出版社、主题和出版年份等，寻找与用户历史偏好相似的候选图书。其优点是可解释性较强，并且在缺少其他用户行为数据时仍然可以工作，因此常用于冷启动处理；其不足是容易过度依赖已有偏好，难以发现用户潜在兴趣。

第二类是协同过滤推荐。该类方法不直接分析图书内容，而是利用用户之间或图书之间的交互模式建立相似性关系。若两个用户对许多图书有相近评分，则可以认为他们的兴趣相似；若两本图书经常被相同用户以相似方式评分，则可以认为这两本图书相似。协同过滤能够发现用户的隐含偏好，但对数据稀疏较为敏感。

第三类是混合推荐。混合推荐的思想是将不同算法按一定规则组合起来，以弥补单一算法的不足。对于图书推荐而言，协同过滤适合挖掘深层兴趣，内容推荐适合处理冷启动和相似图书分析，两者结合往往比单独使用任何一种方法更稳健。本文当前系统即采用混合推荐思想，但具体实现上不是固定加权，而是根据场景和数据质量进行动态路由。

除上述三类外，矩阵分解、深度学习、图神经网络等方法也是推荐系统的重要研究方向。不过这些方法通常需要更复杂的训练过程和更高的工程成本。考虑到本项目的实现目标、数据条件和系统复杂度，本文最终采用了更易解释、便于落地的记忆式协同过滤与内容推荐方法。

#### 2.1.3 推荐系统评价指标

推荐系统的效果评估通常分为离线评估和在线评估两类。当前项目已落地并可复核的是离线评估，因此本文在后续分析中主要采用离线指标。

Precision@K 用于衡量推荐列表前 K 项中真正与用户偏好相关的比例，能够反映推荐结果的准确程度。Recall@K 用于衡量用户真实喜欢的图书中有多少被成功推荐，体现系统对用户兴趣的召回能力。F1-Score@K 是 Precision@K 与 Recall@K 的调和平均，用于综合评价推荐结果的精确性与完整性。

Coverage 用于衡量系统能够覆盖的图书范围，即至少被推荐过一次的图书数占全部图书数的比例。对于图书推荐系统而言，Coverage 较高意味着系统不仅在推荐热门图书，也具备一定的长尾挖掘能力。

基于当前项目的评估脚本，本文主要关注 Precision@10、Recall@10、F1-Score@10 和 Coverage。与点击率、转化率等在线指标不同，这些离线指标可以直接基于已有评分数据复现，更适合当前系统的实现条件和验证方式。

### 2.2 协同过滤算法

#### 2.2.1 协同过滤基本原理

协同过滤的基本思想是利用群体行为模式帮助个体做出选择。在推荐系统中，这一思想通常体现在两种关系上：一类是用户与用户之间的相似关系，另一类是物品与物品之间的相似关系。只要历史交互数据足够，就可以不直接分析图书语义内容，而仅通过评分模式建立推荐依据。

若记用户 \(u\) 和用户 \(v\) 在共同评分图书集合上的评分向量分别为 \(R_u\) 和 \(R_v\)，则二者的余弦相似度可表示为：

\[
sim(u,v)=\frac{R_u \cdot R_v}{\|R_u\| \|R_v\|}
\]

同理，若将图书 \(i\) 与图书 \(j\) 在共同评分用户上的评分表示为向量 \(R_i\) 和 \(R_j\)，则可以用相同方式计算图书之间的相似度。无论是用户协同过滤还是物品协同过滤，其核心都在于“先找相似对象，再据此估计目标对象的偏好分数或相似分数”。

#### 2.2.2 基于用户的协同过滤

基于用户的协同过滤认为，相似用户往往会喜欢相似图书。当前系统在实现上并不与全量用户直接计算相似度，而是先根据共同评分图书筛选候选用户，再进一步计算余弦相似度。这样做的原因在于，高稀疏数据下大部分用户之间根本没有足够的共同评分，直接全量计算既低效也缺乏意义。

在当前代码实现中，系统首先要求目标用户与候选用户至少拥有 2 本共同评分图书，然后对共同评分向量计算余弦相似度，并保留相似度较高的用户作为邻居集合。随后，系统从前若干个相似用户中收集高评分图书，利用相似度加权平均的方式预测目标用户对候选图书的潜在评分：

\[
\hat{r}_{u,i}=\frac{\sum_{v \in N(u)} sim(u,v)\cdot r_{v,i}}{\sum_{v \in N(u)} sim(u,v)}
\]

其中，\(N(u)\) 表示与用户 \(u\) 相似且对图书 \(i\) 有评分的用户集合。预测分数越高，说明该图书越可能符合目标用户偏好。

该方法的优点是能够利用群体行为发现用户未显式表达的潜在兴趣，因此适合用于推荐页的个性化推荐。其局限性在于对用户评分历史较为依赖，当用户评分过少时，难以找到可靠的相似用户。因此，在当前系统中，用户协同过滤并不是唯一策略，而是作为混合推荐中的核心组成部分使用。

#### 2.2.3 基于物品的协同过滤

基于物品的协同过滤认为，如果两本图书经常被相同用户以相近方式评分，那么它们在用户行为层面上就是相似的。与用户协同过滤相比，这种方法更适合图书详情页场景，因为当用户已经明确浏览某一本书时，系统只需回答“还有哪些书与它相似”。

当前系统的实现过程可以概括为三步。首先，找到评分过目标图书的用户集合。其次，以这些用户还评分过的其他图书作为候选集，避免在全库图书中进行无差别比较。最后，对候选图书与目标图书在共同评分用户上的评分向量计算余弦相似度，并返回相似度最高的若干本图书。

该方法的优势在于解释性较强，容易形成“喜欢这本书的用户也喜欢这些书”的推荐逻辑。同时，由于它面向单本目标图书计算相似结果，也便于与内容特征方法进行组合。其不足在于，当目标图书评分过少时，基于评分模式得到的相似图书数量和质量都可能下降，因此在当前系统中，物品协同过滤同样需要与内容特征方法共同使用。

### 2.3 基于内容的推荐算法

#### 2.3.1 基本原理

基于内容的推荐通过分析图书自身特征及用户既有偏好，实现“内容相似”的推荐。与协同过滤不同，这类方法不依赖其他用户是否也喜欢同一本图书，因此更适合在用户行为不足、评分数据不足或者需要解释推荐原因时使用。

在当前系统中，内容推荐并非单一算法，而是包含两类互补逻辑。第一类是基于 TF-IDF 的文本向量推荐，用于已有评分历史的用户和图书内容相似计算；第二类是基于兴趣主题与年龄信息的特征路由，用于冷启动用户。二者共同构成了系统中的内容特征能力。

#### 2.3.2 特征提取方法

当前系统在文本特征提取上采用 TF-IDF 方法，将图书标题、作者和出版社三个字段拼接成组合文本，并使用二元词组范围的 TF-IDF 向量器提取文本特征。为控制稀疏向量规模，系统将文本特征维度限制为 1000 维。除了文本部分外，系统还对出版年份和图书平均评分进行标准化处理，并与 TF-IDF 稀疏向量拼接，形成图书内容表示。

若记某本图书的组合文本为 \(d\)，词项 \(t\) 在文档中的 TF-IDF 权重可写为：

\[
TFIDF(t,d)=TF(t,d)\times IDF(t)
\]

其中，\(TF(t,d)\) 表示词项在文档中的出现频率，\(IDF(t)\) 用于抑制在大量文档中普遍出现的高频词。通过这种方式，系统能够突出更具有区分度的标题、作者和出版社词项。

在实现层面，TF-IDF 特征主要用于两类场景：一是根据用户评分历史构建用户内容画像，生成个性化内容推荐；二是在图书详情页中辅助计算图书与图书之间的内容相似度。

#### 2.3.3 相似度计算

在文本向量空间中，当前系统主要使用余弦相似度衡量用户画像与候选图书、目标图书与候选图书之间的接近程度。若用户内容向量为 \(x\)，候选图书向量为 \(y\)，则其相似度可表示为：

\[
sim(x,y)=\frac{x\cdot y}{\|x\| \|y\|}
\]

余弦相似度关注的是向量方向而非绝对长度，因此特别适用于高维稀疏文本向量。对已有评分历史的用户，系统将其已评分图书向量按评分高低加权求平均，从而得到用户内容画像；随后再计算该画像与候选图书向量的余弦相似度，返回相似度最高的图书作为内容推荐结果。

在具体实现中，系统还会先排除用户已经评分过的图书，并对候选图书增加最低评分人数限制，从而减少质量过低的结果进入推荐列表。

#### 2.3.4 基于内容的推荐在图书领域的应用

在当前图书系统中，内容推荐主要体现为以下三种具体形式。

第一，针对已有评分历史的用户，系统通过用户已评分图书的 TF-IDF 向量构建内容画像，再与候选图书向量计算余弦相似度，从而生成个性化内容推荐。该方法反映的是“你过去喜欢过什么样的图书内容”。

第二，针对没有评分历史的用户，系统采用“兴趣优先、年龄辅助、热门兜底”的特征路由策略。如果用户选择了兴趣主题，则根据 `theme_id` 匹配图书主题，并在必要时结合年龄偏好进行排序；如果用户只有年龄信息，则依据不同年龄段对图书年代的偏好，结合图书质量分数生成结果；如果用户既没有兴趣也没有年龄，则返回评分较高且评价人数较多的优质热门图书。由此可见，当前系统中的冷启动方案并不是地域或国家匹配，而是围绕兴趣主题和年龄信息展开。

第三，在图书详情页中，系统还实现了图书与图书之间的内容相似计算。该部分优先使用 TF-IDF 内容向量与候选图书预筛选，若相关特征不可用，则回退到基于作者、主题、出版社、年份和评分差异的属性匹配方法。这样既保证了相似图书推荐的可解释性，也提高了内容推荐在不同异常情况下的可用性。

### 2.4 混合推荐策略

#### 2.4.1 混合推荐的动机

单一推荐算法通常难以覆盖图书推荐的全部场景。协同过滤依赖用户行为，适合活跃用户，但在冷启动场景中容易失效；内容推荐不依赖其他用户行为，适合补足冷启动，但在深层兴趣挖掘方面通常弱于协同过滤。因此，将两类方法结合起来，是当前系统设计的自然选择。

不过，混合推荐并不意味着简单地给不同算法分配固定权重。在图书场景中，不同用户的评分数量、兴趣信息完整度以及不同图书的评分密度差异都很大。如果始终使用同一组静态权重，就很难让推荐策略与实际数据质量相匹配。因此，本文采用的是“动态混合 + 状态路由”的思路。

#### 2.4.2 混合推荐的主要策略

从推荐系统理论上看，混合策略常见的形式包括加权混合、切换混合和层叠混合。当前系统实际采用的是其中两种思想的结合。

其一是切换混合，即先根据用户状态或图书状态决定当前应当走哪条推荐路径。例如，对于没有评分历史但已选择兴趣主题的用户，系统优先走兴趣推荐而不是协同过滤；对于评分数据较少的目标图书，系统会降低物品协同过滤的权重。

其二是加权混合，即当两类算法都有可用结果时，按照一定比例将结果组合起来。不过这里的“比例”不是预先写死的常数，而是由当前数据质量决定的动态值。正因为如此，当前系统的混合推荐更接近一种工程化的自适应混合方案。

#### 2.4.3 本研究的混合推荐设计

当前系统的混合推荐设计可以分为“推荐页混合”和“图书详情页混合”两部分。

对于推荐页，系统首先判断用户是否有评分历史、是否选择兴趣以及是否填写年龄。若用户同时具有评分历史和兴趣主题，则进入三层混合推荐：先分别生成用户协同过滤结果和 TF-IDF 内容推荐结果，再依据相似用户数量与平均相似度计算协同过滤置信度，将协同过滤占比动态映射到 50% 至 90%，最后对匹配用户兴趣主题的候选图书进行额外加权。若用户有评分历史但没有兴趣，仅保留协同过滤与 TF-IDF 的双层混合；若用户没有评分历史，则转入兴趣推荐、年龄推荐或热门图书兜底策略。

在当前实现中，推荐页动态比例的核心公式可写为：

\[
confidence = \min\left(\frac{N_{similar}}{50},1\right)\times sim_{avg}
\]

\[
ratio_{cf}=0.50+0.40\times confidence
\]

其中，\(N_{similar}\) 表示相似用户数量，\(sim_{avg}\) 表示平均相似度。置信度越高，协同过滤占比越高；置信度越低，内容推荐占比越高。这样的设计使混合比例能够随数据质量变化，而不是停留在固定值。

对于图书详情页，系统首先分别获取物品协同过滤结果和内容特征相似结果。若两类结果都存在，则根据目标图书的评分数量、物品协同过滤候选数量和平均相似度动态计算物品协同过滤占比，其范围大致在 40% 至 85% 之间；若只有其中一类结果可用，则直接退化为纯协同过滤或纯内容推荐；若两类结果都不可用，则继续降级为同作者图书推荐。由此，图书详情页的混合策略本质上是“按目标图书数据质量自适应调节”的混合方案。

#### 2.4.4 混合推荐的优势分析

当前混合推荐策略的优势主要体现在四个方面。第一，它能够覆盖更多用户状态和图书状态，保证系统在评分充分、评分不足和无评分等多种情况下都能返回结果。第二，它能够让协同过滤与内容推荐发挥互补作用，在个性化深度与冷启动支持之间取得平衡。第三，动态比例机制使推荐系统可以随着数据质量变化自动调节策略，而不是依赖人工设定的固定比例。第四，当前实现将不同算法封装在前后端分离和算法服务分层架构下，便于后续继续扩展新的推荐方法或优化已有参数。

### 2.5 相关技术框架

#### 2.5.1 SpringBoot框架

后端采用 Spring Boot 3.1.5 作为基础框架，运行于 Java 17 环境。Spring Boot 在当前系统中的主要作用是提供统一的 REST 接口、组织业务分层以及管理安全认证流程。用户注册、登录、图书查询、评分写入、推荐调用等业务接口均由后端统一暴露。

在安全层面，系统结合 Spring Security 与 JWT 实现无状态认证。公开接口如图书浏览和主题列表可以直接访问，而个人推荐、个人中心和评分等接口则要求携带合法令牌。这样的设计既满足了前后端分离系统的认证需求，也便于前端在刷新页面后恢复用户登录状态。

在数据访问层面，当前系统使用 MyBatis Plus 操作数据库。相比手写大量 SQL，MyBatis Plus 在保留较高可控性的同时降低了基础 CRUD 开发成本，并支持分页查询和条件构造，适合本项目当前的系统规模和开发节奏。

#### 2.5.2 Vue.js框架

前端采用 Vue 3 构建单页应用。Vue 3 的响应式机制能够较好地支撑图书列表、推荐结果、用户信息等界面状态的同步更新，适合交互频繁的推荐系统页面开发。

当前前端同时使用 Vue Router 组织页面跳转，使用 Pinia 管理用户登录状态和本地持久化数据，使用 Axios 封装统一请求入口，并基于 Element Plus 快速搭建表单、列表、分页、提示信息等通用界面组件。围绕这些基础能力，系统实现了首页、登录注册、资料完善、图书浏览、图书详情、评分历史、个人中心和推荐页等核心页面。

#### 2.5.3 Flask框架

算法服务采用 Flask 构建轻量级微服务。与将推荐算法直接写入 Java 后端相比，独立的 Python 服务更适合组织 NumPy、pandas、scikit-learn 等计算逻辑，也便于算法模块的单独迭代。

在当前实现中，Flask 服务负责对外提供用户推荐、相似图书推荐、缓存清理、预计算和健康检查等接口，并在服务启动时完成数据加载与特征提取。后端通过 HTTP 方式调用算法服务，而不是直接共享实现代码，这使系统架构边界更加清晰。

#### 2.5.4 数据处理库

算法服务的核心数据处理依赖于 NumPy、pandas、scikit-learn 和 SciPy。NumPy 负责向量与矩阵运算，pandas 负责评分数据和图书数据的筛选、分组与聚合，scikit-learn 提供 TF-IDF 向量化和余弦相似度计算能力，SciPy 则用于构建和处理稀疏矩阵。这些库共同构成了当前推荐算法实现的基础计算环境。

#### 2.5.5 数据库技术

系统底层采用 MySQL 8.0 存储业务数据。用户表、图书表、评分表和兴趣表共同支撑推荐链路的数据基础：用户表记录年龄等基础信息，图书表记录标题、作者、出版社、年份、主题和评分统计，评分表记录用户与图书之间的显式反馈，兴趣表维护用户与主题之间的多对多关系。

在查询层面，系统依赖主键索引、用户与图书相关索引以及图书标题和作者上的全文检索能力支持分页浏览、关键词搜索和评分统计更新。由于推荐算法服务和后端服务都依赖同一数据库，数据库设计的稳定性直接影响推荐功能的准确性和可用性。
