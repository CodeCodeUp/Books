# 基于协同过滤与内容特征的图书馆资源智能化推荐系统的设计与实现

---

## 第3章 系统需求分析与设计

### 3.1 需求分析

#### 3.1.1 功能性需求分析

系统的功能性需求是指系统应该提供的具体功能和服务。根据图书推荐系统的应用场景和用户需求，本系统的功能性需求可以分为以下几个模块：

**（1）用户管理模块**

用户注册功能：新用户通过填写用户名和密码完成注册。系统为新注册用户分配唯一的用户ID，ID从300001开始自增，与原有数据集的用户ID区分。注册成功后，系统自动生成JWT令牌并返回给客户端，实现无缝自动登录，无需用户手动登录。前端自动保存令牌并跳转到资料完善页面(CompleteProfile)，引导用户完善个人信息。注册过程中，系统对用户名进行唯一性验证，避免重复注册。

资料完善流程：为提升用户体验和推荐质量，系统设计了两步式资料完善流程。第一步要求用户填写年龄信息，年龄将自动转换为年龄组（Under 18、18-24、25-34、35-44、45-54、55+），用于基于内容的推荐。第二步通过Apple风格的3D浮动气泡选择器，让用户从31个图书主题中选择阅读兴趣（如文学、科幻、奇幻、悬疑、浪漫等）。兴趣选择器采用智能网格布局(2×2、3×2或3×3自适应)，每页展示8个主题，支持随机选择和全选功能。用户选择的兴趣主题存储在user_interests表中，用于个性化推荐和用户画像构建。资料完善流程允许跳过，用户可稍后在个人中心补充。

用户登录功能：注册用户通过用户名和密码进行身份验证。系统采用BCrypt算法对密码进行加密存储，登录时验证密码哈希值。验证成功后，系统生成JWT令牌返回给客户端，令牌有效期为24小时。客户端将令牌存储在LocalStorage中，后续请求在HTTP头部携带令牌进行身份认证。

个人信息管理：用户登录后可以查看和修改个人信息，包括昵称、年龄等。年龄信息会自动转换为年龄组，用于内容推荐算法。用户可以在个人中心随时修改密码和编辑阅读兴趣偏好。兴趣管理采用与注册时相同的Apple风格气泡选择器，已选择的兴趣以浅蓝色高亮显示，用户可以添加、删除或重新选择兴趣主题。

登录状态保持：系统通过JWT和前端状态管理实现登录状态的持久化。用户关闭浏览器后重新打开，如果Token未过期，系统自动恢复登录状态，无需重新登录。Token过期后，系统提示用户重新登录。

**（2）图书管理模块**

图书浏览功能：用户可以分页浏览系统中的所有图书。每页默认显示20本图书，展示图书的封面图片、标题、作者、出版年份、平均评分等基本信息。系统支持前端分页控制，用户可以跳转到指定页码或切换每页显示数量。图书按照录入时间倒序排列，保证新书优先展示。

图书搜索功能：用户可以通过关键词搜索图书，支持书名和作者的模糊匹配。系统在MySQL数据库中建立了全文索引，能够快速检索匹配的图书。搜索结果按照相关度和评分综合排序，提升用户体验。搜索功能支持空格分隔的多关键词查询，增强检索灵活性。

图书详情功能：用户点击图书卡片后，进入图书详情页，查看图书的完整信息，包括ISBN、标题、作者、出版社、出版年份、封面图片、平均评分、评分人数等。详情页提供评分功能入口，用户可以对图书进行0-5分的评分（支持0.5分间隔）。评分提交后，系统实时更新图书的平均评分和评分人数。

热门图书展示：系统首页展示热门图书，热门程度通过综合评分和评分人数计算。具体算法为：先筛选评分人数大于等于100的图书，然后按平均评分降序排列，取前20本作为热门推荐。这种方法避免了评分人数少但偶然高分的图书被推荐，确保热门图书的可靠性。

最新图书展示：首页同时展示最新图书，按照出版年份降序排列，取最近5年内出版的图书前20本。最新图书为用户提供了时新内容的获取渠道，满足对新书的需求。

相似图书推荐：在图书详情页，系统展示与当前图书相似的其他图书。相似图书通过物品协同过滤算法和内容特征相似度混合计算得出，70%权重来自协同过滤（基于评分模式相似性），30%权重来自内容特征（基于作者、出版社、出版年份的匹配）。相似图书数量默认为6本，帮助用户发现相关图书。

**（3）评分管理模块**

图书评分功能：用户可以对任意图书进行评分，评分范围为0-5分，支持0.5分间隔（即0、0.5、1.0、1.5...5.0共11个等级）。用户对同一本图书只能评分一次，重复评分时系统自动更新原有评分。评分提交后，系统在数据库中插入或更新评分记录，同时异步更新图书表中的平均评分和评分人数字段。

评分历史查询：用户可以查看自己的历史评分记录，展示已评分图书的标题、作者、评分值、评分时间等信息。评分记录按时间倒序排列，最新评分优先显示。用户可以在评分历史中重新修改评分或删除评分记录。

评分统计展示：图书详情页展示该图书的评分统计信息，包括平均评分、总评分人数、评分分布直方图等。评分分布直方图展示1星、2星、3星、4星、5星的人数占比，帮助用户全面了解图书的评价情况。

**（4）推荐系统模块**

个性化推荐功能：这是系统的核心功能。用户登录后访问推荐页面，系统根据用户的评分历史和用户特征（年龄、兴趣），生成个性化推荐列表。推荐算法采用智能路由的混合策略：

- **三层混合推荐**（有评分+有兴趣）: 70%协同过滤 + 30%TF-IDF内容特征，动态比例调节（50%-90%），对匹配兴趣的图书评分提升30%
- **双层混合推荐**（有评分+有年龄/无特征）: 协同过滤 + TF-IDF内容特征，动态比例混合
- **兴趣主题推荐**（无评分+有兴趣）: 基于user_interests表匹配books.theme_id推荐
- **年龄偏好推荐**（无评分+有年龄）: 基于年龄组偏好推荐适龄图书
- **优质热门图书**（无评分+无特征）: 评分≥4.0且评分人数≥20的热门图书

推荐结果默认展示10本图书，每本图书显示预测评分或推荐理由。系统自动根据用户状态选择最优推荐策略，实现全场景覆盖。

推荐解释功能：为了提升用户对推荐结果的信任度和理解度，系统为每个推荐提供解释信息。协同过滤推荐的解释为"基于与你兴趣相似的用户偏好"；内容推荐的解释为"基于TF-IDF内容相似度匹配"；兴趣推荐的解释为"根据您选择的兴趣主题推荐"；混合推荐综合多种解释。解释信息以标签形式显示在推荐图书卡片上。

推荐刷新机制：用户评分后，系统自动触发推荐更新流程。具体为：用户提交评分 → 后端保存评分到数据库 → 调用推荐算法服务清除该用户的缓存 → 异步预计算新的推荐结果 → 用户下次访问推荐页面时获取更新后的推荐。这一机制确保推荐结果能够及时反映用户最新的阅读偏好。

**（5）系统辅助功能**

用户界面适配：前端界面采用响应式设计，能够适配不同尺寸的设备屏幕，包括桌面浏览器、平板电脑和手机。界面布局在小屏幕下自动调整为单列显示，确保良好的移动端体验。

加载状态提示：系统在进行数据加载和推荐计算时，显示加载动画或进度提示，避免用户长时间等待时的焦虑。推荐计算时显示"正在为您生成个性化推荐..."的提示文字和旋转图标。

错误处理提示：当系统遇到错误（如网络故障、推荐服务不可用、数据库错误）时，显示友好的错误提示信息，引导用户进行相应操作（如刷新页面、稍后重试）。错误信息不暴露技术细节，保证系统安全性。

#### 3.1.2 非功能性需求分析

非功能性需求描述了系统应具备的性能、可靠性、安全性等质量属性。

**（1）性能需求**

响应时间要求：图书浏览、搜索、详情页的响应时间应在2秒以内。推荐计算的响应时间，在缓存命中时应在1秒以内，首次计算或缓存失效时应在30秒以内。为实现这一目标，系统采用了多级缓存策略：推荐结果缓存有效期1小时，相似度计算结果持久化缓存，算法服务启动时全量加载数据到内存。

并发处理能力：系统应支持至少100个并发用户同时访问而不出现明显性能下降。推荐算法服务采用多线程处理，能够并发处理多个推荐请求。数据库连接池设置最大连接数为50，确保高并发下的稳定性。

数据处理规模：系统应能够处理数十万级别的用户、图书和评分数据。本项目实际处理了433,671条评分、271,360本图书、77,805名用户的数据，验证了系统的数据处理能力。随着数据增长，系统通过增量数据更新和候选预筛选优化，保持计算效率。

**（2）可靠性需求**

系统可用性：系统应保持7×24小时稳定运行，年可用性目标为99%。通过合理的异常处理、日志记录和监控机制，及时发现和修复问题。推荐算法服务提供健康检查接口，后端定期检测算法服务状态，当服务不可用时自动降级为热门推荐，确保推荐功能的连续性。

数据一致性：评分数据的写入和更新必须保证事务一致性，避免数据丢失或错误。MySQL的InnoDB存储引擎提供事务支持，确保评分记录和图书统计信息的同步更新。推荐缓存与数据库数据可能存在短暂不一致（最长1小时），但这在推荐系统中是可接受的。

容错能力：系统应具备良好的容错机制。当推荐算法服务不可用时，自动降级为基于规则的推荐（热门图书、最新图书）；当某个推荐算法失败时，切换到备选算法；当数据库查询超时时，返回缓存数据或默认结果。通过多层次的降级策略，保证核心功能的可用性。

**（3）安全性需求**

用户认证与授权：系统采用JWT进行用户身份认证，Token有效期为24小时，过期后需要重新登录。后端API通过Spring Security拦截所有请求，验证Token的合法性。未登录用户只能访问公开页面（首页、图书浏览、图书详情），无法访问个人中心、推荐页面、评分功能等需要登录的资源。

密码安全：用户密码使用BCrypt哈希算法加密存储，BCrypt是一种慢哈希算法，内置盐值，能够有效防止彩虹表攻击和暴力破解。密码强度要求：长度至少6位，建议包含字母和数字的组合。系统不存储明文密码，即使数据库泄露也无法直接获取用户密码。

SQL注入防护：系统使用MyBatis Plus的参数化查询，所有用户输入都通过预编译语句传递，避免SQL注入攻击。对于全文搜索等特殊场景，对用户输入进行转义和验证。

跨站脚本(XSS)防护：前端对用户输入的文本内容进行HTML转义，避免恶意脚本注入。后端返回的数据在前端展示前进行安全处理。

跨域资源共享(CORS)控制：后端配置了严格的CORS策略，只允许特定的前端域名访问API，防止跨站请求伪造(CSRF)攻击。推荐算法服务同样配置CORS，只接受后端服务的请求。

**（4）可维护性需求**

代码可读性：代码应遵循命名规范和编码规范，类名、函数名、变量名语义明确。关键算法和业务逻辑添加详细注释，说明设计思路和实现细节。代码结构清晰，模块职责单一，便于理解和修改。

模块化设计：系统采用分层架构和微服务架构，前端、后端、算法服务各自独立，通过标准接口通信。各模块可以独立开发、测试和部署，降低耦合度。算法的改进和优化不影响Web系统，Web界面的调整不影响算法服务。

日志与监控：系统在关键操作处记录日志，包括用户登录、评分提交、推荐生成、算法调用、异常错误等。日志分为不同级别（INFO、WARN、ERROR），便于问题排查和性能分析。推荐算法服务记录每次推荐请求的参数、执行时间、返回结果，用于性能监控和算法优化。

版本控制：代码使用Git进行版本控制，数据库结构变更采用版本化的SQL脚本管理，确保系统的可追溯性和可回滚性。数据库脚本按照V1.0、V1.1等版本号命名，记录每次结构变更的内容和原因。

**（5）可扩展性需求**

用户规模扩展：系统架构应支持用户数从当前的数万级扩展到百万级。通过数据库主从复制、读写分离、缓存集群等技术，应对用户增长带来的访问压力。

功能扩展能力：系统应便于增加新的推荐算法、新的评价指标、新的用户交互功能。混合推荐框架采用策略模式，新增算法只需实现统一接口并注册到混合器中即可。前端组件化设计，新增页面和功能模块可以快速集成。

数据源扩展：系统应能够方便地接入新的数据源，如豆瓣图书API、Amazon图书信息等。数据加载模块采用适配器模式，通过配置即可切换或增加数据源，无需修改核心业务逻辑。

#### 3.1.3 用户角色分析

本系统面向的主要用户角色为普通读者，根据使用场景可以细分为以下类型：

**（1）新注册用户**

特征：刚注册系统，没有任何评分历史，可能填写或未填写年龄、地理位置等信息。

需求：希望快速了解系统功能，浏览图书，获得初步的推荐。由于缺乏个性化数据，系统为其推荐高质量的热门图书或基于人口统计学特征的图书，降低使用门槛。

推荐策略：如果用户填写了年龄和地理位置，使用基于内容的推荐，匹配适合其年龄组和文化背景的图书；如果未填写，推荐系统内评分最高且评分人数最多的优质图书。

**（2）活跃用户**

特征：有较多的评分历史（评分数量≥10），填写了完整的个人信息，经常访问系统。

需求：希望获得精准的个性化推荐，发现符合自己兴趣但未曾接触的图书，享受推荐的惊喜感和探索乐趣。

推荐策略：采用70%用户协同过滤 + 30%内容特征的混合推荐。协同过滤基于用户的历史偏好和相似用户的行为，挖掘潜在兴趣；内容推荐基于用户特征，增加多样性。混合策略既有个性化，又避免过度窄化。

**（3）偶尔访问用户**

特征：注册后偶尔登录，评分数量较少（评分数量<10），部分信息可能未填写。

需求：希望在有限的交互下获得有价值的推荐，提升系统使用的便利性和满意度。

推荐策略：根据有限的评分历史进行协同过滤推荐，如果评分数量不足以计算可靠的相似用户，则补充热门图书推荐。同时鼓励用户完善个人信息和增加评分，以获得更好的推荐效果。

**（4）特定兴趣用户**

特征：对某个特定领域（如科幻小说、历史传记、技术书籍）有明确偏好，评分集中在该领域。

需求：希望发现该领域内的更多优质图书，同时适当拓展到相关领域。

推荐策略：物品协同过滤能够很好地服务这类用户，推荐与其高分图书相似的其他图书。内容特征推荐基于作者、出版社等信息，推荐同类型图书。混合策略在满足用户核心兴趣的同时，通过用户协同过滤引入一定的多样性。

### 3.2 系统总体设计

#### 3.2.1 系统架构设计

本系统采用前后端分离的架构模式，结合微服务的设计理念，将推荐算法独立部署为微服务，实现业务系统与算法服务的解耦。系统整体分为三层：表示层、应用层和数据层。

**（1）表示层（前端）**

表示层负责用户界面的展示和交互，采用Vue 3框架开发单页应用（SPA）。主要组件包括：

路由管理：Vue Router负责页面路由，定义了首页、登录页、注册页、图书列表页、图书详情页、推荐页面、个人中心等路由。路由守卫机制在用户访问需要登录的页面时，检查Token是否存在和有效，未登录用户自动跳转到登录页。

状态管理：Pinia管理全局状态，包括用户登录状态（userId、username、token）、用户信息（年龄、地理位置）等。登录状态同步到LocalStorage，实现持久化存储。状态变更时，相关组件自动响应更新。

UI组件：基于Element Plus组件库构建界面，使用其提供的表格、表单、分页、对话框、消息提示等组件，提升开发效率和界面一致性。自定义组件包括BookCard（图书卡片）、Header（页面头部）、RatingStars（星级评分）等。

HTTP请求：Axios作为HTTP客户端，封装了与后端API的通信。请求拦截器在每个请求头部自动添加JWT Token，响应拦截器统一处理错误（如Token过期、服务器错误），简化业务代码。

**（2）应用层（后端与算法服务）**

应用层包含两个独立的服务：Web后端服务和推荐算法服务。

Web后端服务基于SpringBoot 3.1.5开发，端口为8080，提供RESTful API。主要模块包括：

控制器层（Controller）：接收前端HTTP请求，解析参数，调用业务逻辑层，返回JSON格式的响应。主要控制器有UserController（用户注册、登录、信息管理）、BookController（图书查询、搜索、详情）、RatingController（评分提交、查询、统计）、RecommendationController（推荐调用、算法信息查询）。

业务逻辑层（Service）：实现核心业务逻辑，包括用户认证、图书管理、评分处理、推荐调用等。RecommendationService负责调用推荐算法服务，处理推荐请求，实现降级策略。

数据访问层（Mapper）：使用MyBatis Plus与MySQL数据库交互，提供CRUD接口。Mapper接口定义了用户、图书、评分的数据操作方法，MyBatis Plus自动生成基础SQL语句，复杂查询通过XML映射文件编写。

安全模块（Security）：Spring Security结合JWT实现身份认证和授权。JwtAuthenticationFilter拦截所有请求，验证Token的有效性，提取用户信息注入到请求上下文。SecurityConfig配置了接口的访问权限，公开接口允许匿名访问，受保护接口需要认证。

推荐算法服务基于Python Flask开发，端口为5000，专注于推荐算法的计算和优化。主要模块包括：

算法实现模块（algorithms）：包含UserBasedCF（用户协同过滤）、ItemBasedCF（物品协同过滤）、ContentBasedFiltering（基于内容的推荐）、HybridRecommendation（混合推荐）四个算法类，每个类实现数据加载、相似度计算、推荐生成等方法。

数据加载模块（data）：DataLoader类负责从MySQL数据库加载评分、图书、用户数据，转换为Pandas DataFrame格式供算法使用。启动时全量加载，后续增量更新。

缓存模块（utils/cache）：RecommendationCache类实现推荐结果的文件缓存，缓存以JSON格式存储在本地文件系统，包含推荐列表、时间戳、算法类型等信息。提供缓存读取、写入、失效、清除等方法。

API接口模块（app.py）：Flask应用定义了HTTP接口，包括/api/recommend/user-based（混合推荐）、/api/recommend/item-based（物品协同过滤）、/api/recommend/similar-items（相似图书）、/api/cache/clear（清除缓存）、/api/cache/precompute（预计算推荐）等。接口接收JSON格式的请求，返回JSON格式的响应。

数据层负责数据的持久化存储，采用MySQL 8.0关系型数据库。数据库设计包括三张核心表和必要的索引。

**（4）系统交互流程**

典型的推荐请求流程如下：

步骤1：用户登录前端系统，浏览器向后端发送POST /users/login请求，携带用户名和密码。

步骤2：后端验证密码，生成JWT Token返回给前端。前端存储Token到LocalStorage和Pinia状态。

步骤3：用户访问推荐页面，前端向后端发送GET /api/recommendations/user-based/{userId}请求，请求头携带Token。

步骤4：后端验证Token有效性，提取用户ID，调用RecommendationService的getUserBasedRecommendations方法。

步骤5：RecommendationService通过RestTemplate向推荐算法服务发送POST http://localhost:5000/api/recommend/user-based请求，传递userId、top_n等参数。

步骤6：推荐算法服务的Flask应用接收请求，调用HybridRecommendation的get_hybrid_user_recommendations方法。

步骤7：HybridRecommendation先检查缓存，如果缓存命中且未过期，直接返回缓存结果；否则，调用UserBasedCF和ContentBasedFiltering计算推荐，按7:3比例混合，生成最终推荐列表，写入缓存。

步骤8：推荐算法服务返回JSON格式的推荐结果给后端。

步骤9：后端将推荐结果封装为统一的Result对象，返回给前端。

步骤10：前端接收推荐数据，渲染图书卡片，展示推荐列表。

用户评分后的缓存更新流程：

步骤1：用户在图书详情页提交评分，前端发送POST /api/ratings请求。

步骤2：后端保存评分到数据库，更新图书的平均评分和评分人数。

步骤3：后端调用推荐算法服务的POST /api/cache/clear接口，传递userId，清除该用户的推荐缓存。

步骤4：后端调用POST /api/cache/precompute接口，异步触发推荐预计算。

步骤5：推荐算法服务在后台线程中，强制刷新数据（从数据库重新加载评分数据），为该用户计算新的推荐结果，写入缓存。

步骤6：用户下次访问推荐页面时，获取更新后的推荐。

这种异步预计算机制，在不影响用户评分操作响应速度的前提下，保证了推荐结果的时效性。

### 3.3 数据库设计

#### 3.3.1 数据库概念设计

数据库的概念设计采用实体-联系（E-R）模型，识别系统中的实体、属性和实体间的关系。

**（1）实体及属性**

用户（User）实体：属性包括用户ID（user_id，主键）、用户名（username，唯一）、密码（password，加密存储）、昵称（nickname）、年龄（age）、年龄组（age_group）、头像URL（avatar_url）、状态（status）、创建时间（created_at）、更新时间（updated_at）、最后登录时间（last_login_at）。

图书（Book）实体：属性包括图书ID（book_id，主键，ISBN）、标题（title）、作者（author）、出版社（publisher）、出版年份（year）、主题分类ID（theme_id，外键）、小图片URL（image_url_s）、中图片URL（image_url_m）、大图片URL（image_url_l）、平均评分（avg_rating）、评分数量（rating_count）、创建时间（created_at）、更新时间（updated_at）。

图书主题（BookTheme）实体：属性包括主题ID（theme_id，主键）、英文名称（theme_name_en，唯一）、中文名称（theme_name_zh）、描述（description）、创建时间（created_at）、更新时间（updated_at）。系统包含31个预定义主题，如Literature(文学)、Science Fiction(科幻)、Fantasy(奇幻)等。

评分（Rating）实体：属性包括评分ID（rating_id，主键，自增）、用户ID（user_id，外键）、图书ID（book_id，外键）、评分值（rating）、评分时间（rating_date）、创建时间（created_at）。

用户兴趣（UserInterest）实体：属性包括记录ID（id，主键，自增）、用户ID（user_id，外键）、主题ID（theme_id，外键）、创建时间（created_at）。用于存储用户选择的阅读兴趣主题。

**（2）实体间关系**

用户与评分：一个用户可以对多本图书评分，一个评分记录属于一个用户。关系为一对多（1:N）。用户通过user_id与评分表关联。

图书与评分：一本图书可以被多个用户评分，一个评分记录对应一本图书。关系为一对多（1:N）。图书通过book_id与评分表关联。

图书与主题：一本图书属于一个主题分类，一个主题包含多本图书。关系为多对一（N:1）。图书通过theme_id与主题表关联。

用户与兴趣主题：一个用户可以选择多个兴趣主题，一个主题可以被多个用户选择。关系为多对多（M:N）。通过user_interests表实现关联，存储用户-主题的偏好数据。

用户与图书：通过评分表建立多对多（M:N）关系。一个用户可以评分多本图书，一本图书可以被多个用户评分。评分表作为关联表，存储用户-图书的交互数据。

#### 3.3.2 数据库逻辑设计

逻辑设计将E-R模型转换为关系模式，定义表结构、数据类型、约束和索引。

**（1）用户表（users）**

```sql
CREATE TABLE `users` (
  `user_id` int NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username` varchar(50) NOT NULL COMMENT '登录用户名',
  `password` varchar(255) NOT NULL COMMENT '加密密码',
  `nickname` varchar(50) DEFAULT NULL COMMENT '昵称',
  `age` int DEFAULT NULL COMMENT '年龄',
  `age_group` varchar(20) DEFAULT NULL COMMENT '年龄分组',
  `avatar_url` varchar(500) DEFAULT NULL COMMENT '头像URL',
  `status` tinyint DEFAULT '1' COMMENT '用户状态（1:正常 0:禁用）',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `last_login_at` timestamp NULL DEFAULT NULL COMMENT '最后登录时间',
  PRIMARY KEY (`user_id`),
  UNIQUE KEY `username` (`username`),
  KEY `idx_username` (`username`),
  KEY `idx_age_group` (`age_group`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB AUTO_INCREMENT=300001 DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

设计说明：
- user_id为自增主键，从300001开始，与原始数据集用户ID区分。
- username设为唯一索引，保证用户名不重复。简化注册流程，不再需要邮箱字段。
- password字段长度255，存储BCrypt哈希后的密码（BCrypt输出60字符，预留空间）。
- age_group用于内容推荐算法和用户画像构建，建立索引加速查询。
- created_at、updated_at自动管理时间戳，记录数据变更历史。
- status字段用于用户的启用/禁用管理，便于后续扩展。

**（2）图书表（books）**

```sql
CREATE TABLE `books` (
  `book_id` varchar(20) NOT NULL COMMENT '图书ID(ISBN)',
  `title` varchar(500) NOT NULL COMMENT '图书标题',
  `author` varchar(200) DEFAULT NULL COMMENT '作者',
  `publisher` varchar(200) DEFAULT NULL COMMENT '出版社',
  `year` int DEFAULT NULL COMMENT '出版年份',
  `theme_id` int DEFAULT NULL COMMENT '图书主题分类ID',
  `image_url_s` varchar(500) DEFAULT NULL COMMENT '小图片URL',
  `image_url_m` varchar(500) DEFAULT NULL COMMENT '中图片URL',
  `image_url_l` varchar(500) DEFAULT NULL COMMENT '大图片URL',
  `avg_rating` decimal(3,2) DEFAULT '0.00' COMMENT '平均评分',
  `rating_count` int DEFAULT '0' COMMENT '评分数量',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`book_id`),
  KEY `idx_author` (`author`),
  KEY `idx_year` (`year`),
  KEY `idx_theme_id` (`theme_id`),
  KEY `idx_avg_rating` (`avg_rating`),
  KEY `idx_title` (`title`(100)),
  KEY `idx_rate` (`rating_count`),
  KEY `idx_created_at` (`created_at`),
  FULLTEXT KEY `idx_search` (`title`,`author`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='图书信息表';
```

设计说明：
- book_id使用ISBN作为主键，类型为varchar(20)，因为ISBN可能包含字母。
- title长度500，支持长标题。author和publisher长度200，满足多作者联合的情况。
- year为int类型，存储出版年份，建立索引支持按年份查询和排序。
- **theme_id字段关联到book_theme表，用于图书主题分类和基于兴趣的推荐**。
- avg_rating为decimal(3,2)，范围0.00-5.00，精度两位小数。rating_count记录评分人数。
- 在title和author上建立全文索引idx_search，支持关键词搜索。全文索引使用MySQL的FULLTEXT特性，搜索效率高于LIKE模糊匹配。
- idx_avg_rating和idx_rate索引用于热门图书查询（按评分和评分人数排序）。
- idx_created_at索引用于最新图书查询（按录入时间排序）。
- idx_theme_id索引用于按主题筛选图书和推荐计算。

**（3）评分表（ratings）**

```sql
CREATE TABLE `ratings` (
  `rating_id` bigint NOT NULL AUTO_INCREMENT COMMENT '评分ID',
  `user_id` int NOT NULL COMMENT '用户ID',
  `book_id` varchar(20) NOT NULL COMMENT '图书ID',

  `rating_date` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '评分时间',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`rating_id`),
  UNIQUE KEY `uk_user_book` (`user_id`,`book_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_book_id` (`book_id`),
  KEY `idx_rating` (`rating`),
  KEY `idx_rating_date` (`rating_date`),
  KEY `idx_time` (`created_at`)
) ENGINE=InnoDB AUTO_INCREMENT=1300000 DEFAULT CHARSET=utf8mb4 COMMENT='用户评分表';
```

设计说明：
- rating_id为自增主键，类型bigint，支持海量评分记录。
- user_id和book_id的联合唯一索引uk_user_book，确保一个用户对同一本书只能有一条评分记录。用户重复评分时，执行UPDATE操作而非INSERT。
- rating为decimal(2,1)，范围0.0-5.0，精度一位小数，支持0.5分间隔。
- idx_user_id索引用于查询某用户的所有评分，idx_book_id索引用于查询某图书的所有评分，这两个索引是协同过滤算法的关键。
- idx_rating_date索引用于按时间查询评分，支持留存验证法的数据划分（按时间顺序分割训练集和测试集）。

**（5）用户兴趣表（user_interests）**

```sql

  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '记录ID',

  KEY `idx_user_id` (`user_id`),
  KEY `idx_theme_id` (`theme_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户阅读兴趣表';
```

设计说明：
- id为自增主键，唯一标识每条兴趣记录。
- user_id和theme_id的联合唯一索引uk_user_theme，确保一个用户对同一主题只能有一条兴趣记录。
- idx_user_id索引用于快速查询某用户的所有兴趣主题，idx_theme_id索引用于查询选择某主题的所有用户。
- 此表实现用户与主题的多对多关系，存储用户在资料完善流程中选择的阅读兴趣，用于构建用户画像和基于兴趣的个性化推荐。
- 用户可随时在个人中心修改兴趣偏好，系统通过删除和插入操作更新此表。

#### 3.3.3 索引设计与优化

索引是提升数据库查询性能的关键。本系统的索引设计遵循以下原则：

**（1）主键索引**

每个表都定义了主键，主键自动创建唯一聚簇索引。users表以user_id为主键，books表以book_id为主键，ratings表以rating_id为主键。聚簇索引决定了数据的物理存储顺序，查询主键时效率最高。

**（2）唯一索引**

在需要保证数据唯一性的列上建立唯一索引，同时加速查询。users表的username为唯一索引，保证用户名不重复，登录时快速查找用户。ratings表的(user_id, book_id)联合唯一索引，保证评分记录不重复。user_interests表的(user_id, theme_id)联合唯一索引，保证兴趣记录不重复。book_theme表的theme_name_en唯一索引，保证主题名称不重复。

**（3）单列索引**

在频繁作为查询条件、排序条件、分组条件的列上建立单列索引。例如books表的author、year、avg_rating、rating_count列，ratings表的user_id、book_id、rating_date列。单列索引适用于单一条件查询，如"查找某作者的所有图书"、"查找某用户的所有评分"。

**（4）联合索引**

对于多列组合查询，建立联合索引提升性能。ratings表的(user_id, book_id)联合索引，不仅保证唯一性，还加速"查找某用户对某图书的评分"查询。联合索引遵循最左前缀原则，查询条件包含索引的左侧列时，索引生效。

**（5）全文索引**

books表在title和author上建立全文索引，支持关键词搜索。全文索引适用于文本字段的模糊匹配，性能优于LIKE '%关键词%'。MySQL的全文索引默认使用自然语言模式，支持中文分词（通过ngram分词器）。

**（6）索引选择性**

索引的选择性（Selectivity）是指索引列中不同值的数量与总行数的比值。选择性高的列（如user_id、book_id）适合建立索引，查询时过滤效果好。选择性低的列（如status只有0和1两个值）建立索引效果不明显，甚至可能降低性能。

本系统中，age_group和country的选择性中等（age_group有6个值，country有数百个值），建立索引能够支持内容推荐算法的查询，但不是高优先级索引。

**（7）索引维护开销**

索引加速查询的同时，增加了插入、更新、删除操作的开销，因为需要同步维护索引结构。因此，索引不是越多越好，应该根据实际查询需求建立。

ratings表是高频写入表（用户频繁评分），索引数量应适度。本系统在rating_id主键、(user_id, book_id)联合唯一索引、user_id单列索引、book_id单列索引上建立索引，满足了协同过滤算法和评分查询的需求，同时控制了索引数量。

### 3.4 推荐算法设计

#### 3.4.1 用户协同过滤算法设计

用户协同过滤算法的目标是为目标用户推荐与其兴趣相似的其他用户喜欢的图书。算法的核心是计算用户间的相似度，基于相似度预测评分。

**（1）算法流程设计**

输入：目标用户ID（user_id）、推荐数量（top_n，默认10）、最小评分阈值（min_rating，默认3.0）。

输出：推荐图书列表，每个图书包含book_id、title、author、predicted_rating等信息。

流程步骤：

步骤1：数据加载。从数据库加载评分数据、图书数据。评分数据转换为Pandas DataFrame，包含user_id、book_id、rating三列。图书数据包含book_id、title、author等列。

步骤2：候选用户预筛选。获取目标用户的评分记录，提取其评分过的图书集合target_books。在评分数据中筛选出也评分过target_books中图书的其他用户，作为候选相似用户。这一步骤将候选用户从全量用户缩小到有共同评分图书的用户，显著降低计算量。

步骤3：相似度计算。对于每个候选用户other_user，提取其评分记录，找到与目标用户的共同评分图书common_books。如果共同图书数量小于最小阈值（如2本），跳过该用户。提取目标用户和候选用户在共同图书上的评分向量，计算余弦相似度：

sim(target_user, other_user) = (R_target · R_other) / (||R_target|| × ||R_other||)

其中R_target和R_other为评分向量，只包含共同图书的评分。如果相似度大于阈值（如0.3），将该用户加入相似用户列表。

步骤4：邻居选择。按相似度降序排列相似用户，选择Top-K个（如K=50）作为邻居集合。

步骤5：候选图书收集。遍历邻居用户，收集他们评分过但目标用户未评分的图书，作为候选推荐集合。同时记录每个候选图书的邻居评分和相似度。

步骤6：评分预测。对于每个候选图书book，计算预测评分：

predicted_rating(target_user, book) = Σ(sim(target_user, neighbor) × rating(neighbor, book)) / Σsim(target_user, neighbor)

其中求和遍历评分过该图书的邻居。预测评分反映了相似用户对该图书的加权平均偏好。

步骤7：推荐生成。筛选预测评分大于等于min_rating的候选图书，按预测评分降序排列，取Top-N作为推荐结果。查询图书详细信息，返回包含book_id、title、author、predicted_rating的推荐列表。

**（2）性能优化策略**

候选用户预筛选：通过共同评分图书索引，避免与全量用户计算相似度。这一优化将时间复杂度从O(|U|²|I|)降低到O(k|I|)，其中k为平均候选用户数，通常远小于|U|。

相似度计算优化：使用NumPy的向量化操作计算余弦相似度，避免Python循环。NumPy底层使用C实现，性能优于纯Python。对于大规模数据，使用Scipy的sparse matrix表示评分矩阵，节省内存。

候选图书预筛选：只收集邻居用户的高分图书（评分≥3.0）作为候选，减少预测计算量。低分图书不太可能被推荐，可以直接过滤。

缓存机制：推荐结果缓存在本地文件系统，缓存文件命名为user_{user_id}_recommendations.json，包含推荐列表和时间戳。访问推荐时，先检查缓存是否存在且未过期（有效期1小时），命中缓存直接返回，避免重复计算。

异步预计算：用户评分后，系统异步触发推荐预计算。后台线程刷新数据、计算推荐、写入缓存，不阻塞用户操作。下次用户访问推荐页面时，缓存已准备好，响应迅速。

**（3）边界情况处理**

新用户处理：新用户没有评分历史，无法计算相似用户。系统返回空的协同过滤推荐，切换到内容推荐或热门推荐。

评分少的用户：评分数量少于5的用户，共同评分图书少，相似度计算不可靠。系统降低相似度阈值或扩大邻居数量，尽量提供推荐。如果仍无法生成推荐，补充热门图书。

孤立用户：某些用户的评分图书非常小众，没有其他用户评分过这些图书，无法找到相似用户。系统记录日志，返回空推荐，建议用户增加评分。

#### 3.4.2 物品协同过滤算法设计

物品协同过滤算法用于图书详情页的"相似图书推荐"，计算物品间的相似度，推荐与当前图书相似的其他图书。

**（1）算法流程设计**

输入：目标图书ID（book_id）、相似图书数量（top_k，默认6）。

输出：相似图书列表，每个图书包含book_id、title、author、similarity等信息。

流程步骤：

步骤1：获取目标图书的评分用户。从评分数据中筛选出评分过目标图书的用户集合target_users。

步骤2：候选图书预筛选。在评分数据中筛选出target_users评分过的所有其他图书，作为候选相似图书集合。这一步骤将候选范围从全部图书（数十万本）缩小到数千本，大幅减少计算量。

步骤3：相似度计算。对于每个候选图书other_book，找到同时评分过目标图书和候选图书的共同用户common_users。如果共同用户数量小于最小阈值（如2个），跳过该图书。提取目标图书和候选图书在共同用户上的评分向量，计算余弦相似度：

sim(target_book, other_book) = (R_target · R_other) / (||R_target|| × ||R_other||)

其中R_target和R_other为评分向量，只包含共同用户的评分。

步骤4：相似图书排序。按相似度降序排列候选图书，取Top-K作为相似图书推荐。查询图书详细信息，返回包含book_id、title、author、similarity的列表。

**（2）性能优化策略**

候选图书预筛选：通过目标图书的评分用户索引，快速筛选候选图书。避免与全部图书计算相似度，计算时间从数十分钟缩短到几秒。

批量处理：使用Pandas的groupby操作，对候选图书按book_id分组，每组包含该图书的所有评分。避免重复查询数据库，减少I/O开销。

相似度缓存：物品相似度相对稳定（图书内容不变），可以持久化缓存。计算得到的相似度存储在文件或数据库中，下次直接读取，避免重复计算。缓存更新策略：当某图书有新评分时，清除该图书的相似度缓存，按需重新计算。

**（3）冷启动处理**

新图书处理：新上架的图书没有评分，无法计算相似度。系统可以基于内容特征（作者、出版社、年份）推荐同作者或同类型的图书作为替代。

评分少的图书：评分数量少于5的图书，共同评分用户少，相似度不可靠。系统设置更低的共同用户阈值，或结合内容特征计算相似度。

#### 3.4.3 基于内容的推荐算法设计

基于内容的推荐算法利用用户人口统计学特征（年龄组、国家）与图书元数据特征（出版年份、作者、出版社）的匹配关系，为用户推荐适合的图书。主要用于新用户冷启动和协同过滤的补充。

**（1）用户特征提取**

从用户信息中提取以下特征：
- 年龄组（age_group）：将年龄划分为标准年龄段，包括Under 18、18-24、25-34、35-44、45-54、55+。注册时用户填写年龄，系统自动转换为年龄组。
- 国家（country）：从用户填写的地理位置（location）中提取国家信息。使用字符串匹配或地理数据库，将位置转换为标准国家名称。

**（2）图书特征提取**

从图书数据中提取以下特征：
- 出版年份（year）：直接使用图书的出版年份字段。
- 作者（author）：图书的作者信息，用于判断作者风格和文化背景。
- 出版社（publisher）：图书的出版社，一定程度反映图书类型和质量。
- 平均评分（avg_rating）：图书的质量指标。
- 评分人数（rating_count）：图书的受欢迎程度指标。

**（3）匹配策略设计**

年龄组匹配（权重50%）：基于不同年龄段对图书年代的偏好差异，设计匹配规则。

- Under 18（青少年）：偏好新书，2005年后出版的图书匹配分数1.0，2000-2005年图书0.8，更早的图书0.6。青少年倾向于阅读当代流行内容，对经典兴趣较低。
- 18-24（大学生/职场新人）：偏好现代书籍，2000年后出版的图书匹配分数1.0，1990-2000年0.7，更早0.5。这一年龄段追求时代感和实用性。
- 25-34（青年）：偏好当代文学，1990年后出版的图书匹配分数1.0，1980-1990年0.8，更早0.6。青年既关注现代内容，也欣赏成熟作品。
- 35-44（中年）：均衡偏好，1980年后出版的图书匹配分数1.0，1970-1980年0.9，更早0.7。中年读者阅历丰富，接受度广。
- 45-54（成熟期）：偏好经典，1970年后出版的图书匹配分数1.0，1960-1970年0.9，更早0.8。这一年龄段重视内容深度和文学价值。
- 55+（老年）：偏好传统经典，1990年前出版的图书匹配分数1.0，1990-2000年0.8，2000年后0.6。老年读者倾向于回顾经典，对流行文化兴趣较低。

地域文化匹配（权重30%）：基于用户国家与图书作者、出版社的文化关联性，计算匹配分数。

- 英语国家用户（美国、英国、加拿大、澳大利亚）：偏好英语作者的作品，通过作者姓名判断（如姓名为常见英文姓氏）。如果图书作者为英语作者，匹配分数0.8，否则0.5。
- 欧洲国家用户（德国、法国、西班牙、意大利）：偏好欧洲主题的图书，通过书名、作者姓名、出版社判断（如包含欧洲地名、人名）。如果图书为欧洲主题，匹配分数0.8，否则0.5。
- 其他国家用户：不进行特殊匹配，所有图书的地域匹配分数均为0.5。

图书质量匹配（权重20%）：综合图书的平均评分和评分人数，计算质量分数。

quality_score = (avg_rating / 5.0 + min(1.0, rating_count / 100)) / 2

该公式兼顾了评分高低和评分可靠性。评分人数少于100的图书，评分可靠性折扣；评分人数超过100的图书，可靠性视为满分。两者平均得到质量分数。

最终匹配分数为三者加权和：

match_score = 0.5 × 年龄组匹配分数 + 0.3 × 地域匹配分数 + 0.2 × 质量分数

**（4）推荐生成流程**

输入：用户ID（user_id）、推荐数量（top_n）。

输出：推荐图书列表。

流程步骤：

步骤1：获取用户信息，提取年龄组和国家特征。如果用户未填写这些信息，返回空的内容推荐。

步骤2：筛选候选图书。从图书数据中筛选出用户未评分过的图书，作为候选集。同时筛选质量图书（评分人数≥5），过滤掉数据不足的图书。

步骤3：计算匹配分数。对每个候选图书，计算年龄组匹配分数、地域匹配分数、质量分数，加权得到最终匹配分数。

步骤4：排序推荐。按匹配分数降序排列候选图书，取Top-N作为推荐结果。返回包含book_id、title、author、match_score的列表。

**（5）优势与局限**

优势：解决了协同过滤的冷启动问题，新用户无评分历史也能获得推荐。基于人口统计学特征，推荐具有可解释性，用户容易理解。计算简单快速，无需复杂的相似度计算。

局限：推荐结果依赖用户是否填写年龄和地理位置，未填写的用户无法使用。匹配规则基于经验假设，可能不完全符合个体差异。推荐范围受限于用户特征，难以发现跨领域的惊喜内容。

#### 3.4.4 混合推荐策略设计

混合推荐策略通过组合用户协同过滤、物品协同过滤和基于内容的推荐，提供全场景覆盖的推荐服务。

**（1）推荐页面的混合策略**

决策树逻辑：

判断用户是否有评分历史（评分数量≥1）。
- 如果有评分历史：
  - 判断用户是否填写了年龄和地理位置。
    - 如果填写了：采用70%用户协同过滤 + 30%内容推荐的混合策略。
    - 如果未填写：纯用户协同过滤推荐。
- 如果无评分历史：
  - 判断用户是否填写了年龄和地理位置。
    - 如果填写了：纯内容推荐。
    - 如果未填写：推荐系统内评分最高且评分人数最多的优质图书（热门推荐）。

混合算法实现：

70%协同过滤 + 30%内容推荐的混合流程：

步骤1：调用用户协同过滤算法，生成推荐列表cf_recommendations，数量为10。

步骤2：调用内容推荐算法，生成推荐列表content_recommendations，数量为10。

步骤3：从cf_recommendations中取前7本图书（70%）。

步骤4：从content_recommendations中筛选不在cf_recommendations中的图书，取前3本（30%）。这一步骤确保混合结果无重复。

步骤5：合并两个列表，得到最终推荐列表，数量为10。

如果某一算法返回的推荐数量不足（如协同过滤只返回5本），则补充另一算法的推荐，确保总数为10本。

**（2）图书详情页的混合策略**

图书详情页的相似图书推荐，采用70%物品协同过滤 + 30%内容特征相似的混合方案。

物品协同过滤：基于评分模式计算图书相似度，推荐评分模式相似的图书。

内容特征相似：基于作者、出版社、出版年份计算内容相似度，推荐内容相关的图书。

混合流程与推荐页面类似，取物品协同过滤的前4-5本，内容相似的前1-2本，合并去重后返回6本相似图书。

**（3）降级策略**

当推荐算法服务不可用时，后端自动降级为基于规则的推荐：

降级方案1：推荐评分最高且评分人数超过100的热门图书。这一方案不依赖算法服务，直接从数据库查询，保证推荐功能的可用性。

降级方案2：推荐用户评分过的图书的同作者图书。查询用户历史评分中的作者列表，推荐这些作者的其他高分图书。这一方案提供了一定的个性化，计算简单。

降级方案3：推荐最新出版的高评分图书。按出版年份降序和评分降序排列，取前10本。这一方案确保推荐内容的时新性。

后端通过定期健康检查（调用算法服务的/health接口），判断服务状态。如果健康检查失败，启用降级策略。当服务恢复后，自动切换回正常推荐。

```python

                         sep=';', encoding='latin-1',
                         names=['user_id', 'isbn', 'rating'])

# 标准化评分到1-5分制

user_counts = explicit_ratings['user_id'].value_counts()
active_users = user_counts[user_counts >= 5].index
filtered_ratings = explicit_ratings[explicit_ratings['user_id'].isin(active_users)]

# 过滤热门图书：至少被3个用户评分
book_counts = filtered_ratings['isbn'].value_counts()
popular_books = book_counts[book_counts >= 3].index
```

#### 4.3.1 数据加载模块实现

数据加载模块负责从MySQL数据库读取评分、图书、用户数据，转换为Pandas DataFrame格式供算法使用。代码位于data/data_loader.py。

```python
import pandas as pd
import pymysql
from sqlalchemy import create_engine
import logging

logger = logging.getLogger(__name__)

class DataLoader:
    def __init__(self):
        self.db_config = {
            'host': '116.205.244.106',
            'port': 3306,
            'user': 'root',
            'password': '202358hjq',
            'database': 'book_recommendation',
            'charset': 'utf8mb4'
        }
        self.engine = None
        self.last_update_time = None
        self.ratings_df = None
        self.books_df = None
        self.users_df = None

    def initialize_data(self):
        """启动时全量加载数据"""
        logger.info("开始全量加载数据...")
        self.engine = create_engine(
            f"mysql+pymysql://{self.db_config['user']}:{self.db_config['password']}"
            f"@{self.db_config['host']}:{self.db_config['port']}/{self.db_config['database']}"
        )

        # 加载评分数据
        ratings_query = "SELECT user_id, book_id, rating FROM ratings WHERE rating > 0"
        self.ratings_df = pd.read_sql(ratings_query, self.engine)
        logger.info(f"加载评分数据: {len(self.ratings_df)} 条")

        # 加载图书数据
        books_query = "SELECT book_id, title, author, publisher, year, avg_rating, rating_count FROM books"
        self.books_df = pd.read_sql(books_query, self.engine)
        logger.info(f"加载图书数据: {len(self.books_df)} 本")

        # 加载用户数据
        users_query = "SELECT user_id, age, age_group, country FROM users"
        self.users_df = pd.read_sql(users_query, self.engine)
        logger.info(f"加载用户数据: {len(self.users_df)} 人")

        self.last_update_time = pd.Timestamp.now()
        logger.info("数据加载完成")

    def get_ratings_data(self, force_refresh=False):
        """获取评分数据，支持增量更新"""
        if force_refresh or self.ratings_df is None:
            # 强制刷新或首次加载
            ratings_query = "SELECT user_id, book_id, rating FROM ratings WHERE rating > 0"
            self.ratings_df = pd.read_sql(ratings_query, self.engine)
        else:
            # 增量更新：查询上次更新后的新评分
            query = f"""
            SELECT user_id, book_id, rating
            FROM ratings
            WHERE rating > 0 AND created_at > '{self.last_update_time}'
            """
            new_ratings = pd.read_sql(query, self.engine)

            if not new_ratings.empty:
                # 合并新评分，去重（用户对同一图书多次评分保留最新）
                self.ratings_df = pd.concat([self.ratings_df, new_ratings])
                self.ratings_df.drop_duplicates(subset=['user_id', 'book_id'], keep='last', inplace=True)
                logger.info(f"增量更新评分数据: {len(new_ratings)} 条新评分")
                self.last_update_time = pd.Timestamp.now()

        return self.ratings_df

    def get_books_data(self, force_refresh=False):
        """获取图书数据"""
        if force_refresh or self.books_df is None:
            books_query = "SELECT book_id, title, author, publisher, year, avg_rating, rating_count FROM books"
            self.books_df = pd.read_sql(books_query, self.engine)
        return self.books_df

    def get_users_data(self):
        """获取用户数据"""
        if self.users_df is None:
            users_query = "SELECT user_id, age, age_group, country FROM users"
            self.users_df = pd.read_sql(users_query, self.engine)
        return self.users_df
```

设计要点：
- initialize_data方法在服务启动时调用，全量加载数据到内存，避免后续频繁数据库查询。
- get_ratings_data支持增量更新，查询上次更新时间后的新评分，合并到已有数据并去重。
- force_refresh参数允许强制刷新数据，用于用户评分后需要立即获取最新评分的场景。
- 使用SQLAlchemy的create_engine创建连接池，提升并发查询性能。

#### 4.3.2 用户协同过滤算法实现

用户协同过滤算法的完整代码位于algorithms/collaborative_filtering.py，核心方法包括相似用户发现、评分预测、推荐生成。

```python
import numpy as np
import pandas as pd
from sklearn.metrics.pairwise import cosine_similarity
import logging

logger = logging.getLogger(__name__)

class UserBasedCollaborativeFiltering:
    def __init__(self):
        self.data_loader = DataLoader()
        self.cache = RecommendationCache()
        self.ratings_df = None
        self.books_df = None

    def load_data(self):
        """加载数据"""
        if self.ratings_df is None:
            self.data_loader.initialize_data()
        self.ratings_df = self.data_loader.get_ratings_data()
        self.books_df = self.data_loader.get_books_data()

    def find_similar_users_efficient(self, target_user_id, min_common_items=2, top_k=50):
        """高效查找相似用户"""
        # 获取目标用户的评分记录
        target_ratings = self.ratings_df[self.ratings_df['user_id'] == target_user_id]

        if target_ratings.empty:
            logger.warning(f"用户 {target_user_id} 没有评分记录")
            return []

        target_books = set(target_ratings['book_id'].values)
        target_ratings_dict = dict(zip(target_ratings['book_id'], target_ratings['rating']))

        # 候选用户预筛选：找评分过相同图书的用户
        common_users_df = self.ratings_df[
            self.ratings_df['book_id'].isin(target_books) &
            (self.ratings_df['user_id'] != target_user_id)
        ]

        # 按用户分组，计算共同评分图书数量
        common_counts = common_users_df.groupby('user_id')['book_id'].count()
        qualified_users = common_counts[common_counts >= min_common_items].index

        logger.info(f"候选用户数量: {len(qualified_users)}")

        # 计算相似度
        similarities = []
        for other_user_id in qualified_users:
            if len(similarities) >= top_k * 3:
                break

            similarity = self._calculate_user_similarity(
                target_user_id, other_user_id, target_ratings_dict
            )

            if similarity > 0.3:  # 相似度阈值
                similarities.append({
                    'user_id': other_user_id,
                    'similarity': similarity
                })

        # 排序
        similarities.sort(key=lambda x: x['similarity'], reverse=True)
        return similarities[:top_k]

    def _calculate_user_similarity(self, user1_id, user2_id, user1_ratings_dict):
        """计算两个用户的余弦相似度"""
        user2_ratings = self.ratings_df[self.ratings_df['user_id'] == user2_id]
        user2_ratings_dict = dict(zip(user2_ratings['book_id'], user2_ratings['rating']))

        # 找共同评分的图书
        common_books = set(user1_ratings_dict.keys()) & set(user2_ratings_dict.keys())

        if len(common_books) < 2:
            return 0.0

        # 构建评分向量
        vector1 = np.array([user1_ratings_dict[book] for book in common_books])
        vector2 = np.array([user2_ratings_dict[book] for book in common_books])

        # 计算余弦相似度
        similarity = cosine_similarity([vector1], [vector2])[0][0]
        return float(similarity)

    def get_recommendations(self, user_id, top_n=10, min_rating=3.0):
        """生成推荐"""
        # 检查缓存
        cached = self.cache.get_cached_recommendations(user_id)
        if cached:
            logger.info(f"返回缓存的推荐结果")
            return cached['recommendations'][:top_n]

        # 查找相似用户
        similar_users = self.find_similar_users_efficient(user_id)

        if not similar_users:
            logger.warning(f"未找到相似用户，返回空推荐")
            return []

        # 收集候选图书
        user_rated_books = set(
            self.ratings_df[self.ratings_df['user_id'] == user_id]['book_id'].values
        )

        candidate_books = {}

        for similar_user in similar_users[:20]:  # 取前20个相似用户
            similar_user_id = similar_user['user_id']
            similarity = similar_user['similarity']

            # 获取相似用户的高分图书（评分>=3.0）
            similar_user_ratings = self.ratings_df[
                (self.ratings_df['user_id'] == similar_user_id) &
                (self.ratings_df['rating'] >= 3.0)
            ]

            for _, row in similar_user_ratings.iterrows():
                book_id = row['book_id']
                rating = row['rating']

                if book_id not in user_rated_books:
                    if book_id not in candidate_books:
                        candidate_books[book_id] = []
                    candidate_books[book_id].append((similarity, rating))

        # 预测评分
        predictions = []
        for book_id, ratings_data in candidate_books.items():
            # 加权平均
            weighted_sum = sum(sim * rating for sim, rating in ratings_data)
            similarity_sum = sum(sim for sim, rating in ratings_data)

            predicted_rating = weighted_sum / similarity_sum if similarity_sum > 0 else 0

            if predicted_rating >= min_rating:
                predictions.append({
                    'book_id': book_id,
                    'predicted_rating': predicted_rating
                })

        # 排序
        predictions.sort(key=lambda x: x['predicted_rating'], reverse=True)

        # 查询图书详情
        recommendations = []
        for pred in predictions[:top_n]:
            book_info = self.books_df[self.books_df['book_id'] == pred['book_id']]
            if not book_info.empty:
                book = book_info.iloc[0]
                recommendations.append({
                    'bookId': pred['book_id'],
                    'title': book['title'],
                    'author': book['author'],
                    'predictedRating': round(pred['predicted_rating'], 2),
                    'algorithm': 'user_based_cf'
                })

        # 缓存结果
        self.cache.save_recommendations(user_id, recommendations, 'user_based_cf')

        return recommendations
```

关键优化：
- find_similar_users_efficient通过共同评分图书索引预筛选候选用户，避免全量计算。
- 使用NumPy和scikit-learn的cosine_similarity计算余弦相似度，性能优于纯Python循环。
- 只收集相似用户的高分图书（≥3.0分）作为候选，减少预测计算量。
- 推荐结果缓存到文件，有效期1小时，减少重复计算。

#### 4.3.3 缓存模块实现

缓存模块负责推荐结果的读取、写入、失效和清除。代码位于utils/cache.py。

```python
import os
import json
import time
import logging

logger = logging.getLogger(__name__)

class RecommendationCache:
    def __init__(self, cache_dir='models/cache', cache_duration=3600):
        self.cache_dir = cache_dir
        self.cache_duration = cache_duration  # 缓存有效期（秒）

        # 创建缓存目录
        if not os.path.exists(cache_dir):
            os.makedirs(cache_dir)

    def get_cached_recommendations(self, user_id):
        """获取缓存的推荐结果"""
        cache_file = os.path.join(self.cache_dir, f"user_{user_id}_recommendations.json")

        if not os.path.exists(cache_file):
            return None

        try:
            with open(cache_file, 'r', encoding='utf-8') as f:
                cache_data = json.load(f)

            # 检查缓存是否过期
            cache_time = cache_data.get('timestamp', 0)
            if time.time() - cache_time > self.cache_duration:
                logger.info(f"用户 {user_id} 的缓存已过期")
                return None

            logger.info(f"命中缓存: 用户 {user_id}")
            return cache_data

        except Exception as e:
            logger.error(f"读取缓存失败: {e}")
            return None

    def save_recommendations(self, user_id, recommendations, algorithm):
        """保存推荐结果到缓存"""
        cache_file = os.path.join(self.cache_dir, f"user_{user_id}_recommendations.json")

        cache_data = {
            'user_id': user_id,
            'recommendations': recommendations,
            'algorithm': algorithm,
            'timestamp': time.time()
        }

        try:
            with open(cache_file, 'w', encoding='utf-8') as f:
                json.dump(cache_data, f, ensure_ascii=False, indent=2)
            logger.info(f"缓存推荐结果: 用户 {user_id}, 数量 {len(recommendations)}")
        except Exception as e:
            logger.error(f"保存缓存失败: {e}")

    def invalidate_user_cache(self, user_id):
        """清除用户的推荐缓存"""
        cache_file = os.path.join(self.cache_dir, f"user_{user_id}_recommendations.json")

        if os.path.exists(cache_file):
            os.remove(cache_file)
            logger.info(f"已清除用户 {user_id} 的缓存")
```

设计特点：
- 缓存以JSON格式存储在文件系统，包含推荐列表、算法类型、时间戳。
- get_cached_recommendations检查缓存文件是否存在、是否过期，过期自动失效。
- invalidate_user_cache在用户评分后调用，清除缓存，确保推荐时效性。
- 缓存有效期设为3600秒（1小时），平衡了时效性和计算成本。

#### 4.3.4 物品协同过滤算法实现

物品协同过滤算法用于计算图书间的相似度,推荐与用户已评分图书相似的其他图书。代码位于algorithms/item_based_cf.py。

```python
import numpy as np
import pandas as pd
from sklearn.metrics.pairwise import cosine_similarity
import logging

logger = logging.getLogger(__name__)

class ItemBasedCollaborativeFiltering:
    def __init__(self, shared_data_loader=None):
        if shared_data_loader:
            self.data_loader = shared_data_loader
        else:
            self.data_loader = DataLoader()
        self.cache = RecommendationCache()
        self.ratings_df = None
        self.books_df = None
        self.item_similarity_cache = {}  # 物品相似度缓存

    def load_data(self):
        """加载数据"""
        self.ratings_df = self.data_loader.get_ratings_data()
        self.books_df = self.data_loader.get_books_data()

    def calculate_item_similarity(self, item1_id, item2_id):
        """计算两个物品的余弦相似度"""
        # 获取评分过这两本书的用户
        item1_ratings = self.ratings_df[self.ratings_df['book_id'] == item1_id]
        item2_ratings = self.ratings_df[self.ratings_df['book_id'] == item2_id]

        # 找共同评分用户
        common_users = set(item1_ratings['user_id']) & set(item2_ratings['user_id'])

        if len(common_users) < 2:
            return 0.0

        # 构建评分向量
        item1_dict = dict(zip(item1_ratings['user_id'], item1_ratings['rating']))
        item2_dict = dict(zip(item2_ratings['user_id'], item2_ratings['rating']))

        vector1 = np.array([item1_dict[user] for user in common_users])
        vector2 = np.array([item2_dict[user] for user in common_users])

        # 计算余弦相似度
        similarity = cosine_similarity([vector1], [vector2])[0][0]
        return float(similarity)

    def find_similar_items(self, target_item_id, top_k=10):
        """查找相似图书"""
        # 检查缓存
        cache_key = f"item_{target_item_id}_similar"
        if cache_key in self.item_similarity_cache:
            return self.item_similarity_cache[cache_key]

        # 获取评分过目标图书的用户
        target_users = set(
            self.ratings_df[self.ratings_df['book_id'] == target_item_id]['user_id']
        )

        if not target_users:
            return []

        # 候选图书预筛选：这些用户评分过的其他图书
        candidate_items = set(
            self.ratings_df[self.ratings_df['user_id'].isin(target_users)]['book_id']
        )
        candidate_items.discard(target_item_id)

        # 计算相似度
        similarities = []
        for candidate_id in candidate_items:
            similarity = self.calculate_item_similarity(target_item_id, candidate_id)
            if similarity > 0.1:
                similarities.append({
                    'book_id': candidate_id,
                    'similarity': similarity
                })

        # 排序并缓存
        similarities.sort(key=lambda x: x['similarity'], reverse=True)
        result = similarities[:top_k]
        self.item_similarity_cache[cache_key] = result

        return result

    def get_recommendations(self, user_id, top_n=10, min_rating=3.0):
        """基于物品的协同过滤推荐"""
        if self.ratings_df is None:
            self.load_data()

        # 获取用户评分的高分图书（>=4.0分）
        user_ratings = self.ratings_df[
            (self.ratings_df['user_id'] == user_id) &
            (self.ratings_df['rating'] >= 4.0)
        ]

        if user_ratings.empty:
            logger.warning(f"用户 {user_id} 没有高分评分记录")
            return []

        user_rated_books = set(
            self.ratings_df[self.ratings_df['user_id'] == user_id]['book_id']
        )

        # 收集候选图书
        candidate_scores = {}

        for _, row in user_ratings.iterrows():
            book_id = row['book_id']
            user_rating = row['rating']

            # 查找相似图书
            similar_items = self.find_similar_items(book_id, top_k=20)

            for similar in similar_items:
                similar_book_id = similar['book_id']
                similarity = similar['similarity']

                # 跳过已评分图书
                if similar_book_id in user_rated_books:
                    continue

                # 加权累计分数
                if similar_book_id not in candidate_scores:
                    candidate_scores[similar_book_id] = {
                        'weighted_sum': 0,
                        'weight_sum': 0
                    }

                weight = similarity * user_rating
                candidate_scores[similar_book_id]['weighted_sum'] += weight
                candidate_scores[similar_book_id]['weight_sum'] += similarity

        # 计算预测评分
        predictions = []
        for book_id, scores in candidate_scores.items():
            predicted_rating = scores['weighted_sum'] / scores['weight_sum']

            if predicted_rating >= min_rating:
                predictions.append({
                    'book_id': book_id,
                    'predicted_rating': predicted_rating
                })

        # 排序
        predictions.sort(key=lambda x: x['predicted_rating'], reverse=True)

        # 查询图书详情
        recommendations = []
        for pred in predictions[:top_n]:
            book_info = self.books_df[self.books_df['book_id'] == pred['book_id']]
            if not book_info.empty:
                book = book_info.iloc[0]
                recommendations.append({
                    'bookId': pred['book_id'],
                    'title': book['title'],
                    'author': book['author'],
                    'predictedRating': round(pred['predicted_rating'], 2),
                    'algorithm': 'item_based_cf'
                })

        return recommendations
```

物品协同过滤的优势是相似度相对稳定,可以持久化缓存。缺点是对于新图书和评分少的图书,相似度计算不可靠。

#### 4.3.5 基于内容的推荐算法实现

基于内容的推荐算法利用用户人口统计学特征匹配图书特征。相关代码逻辑在混合推荐类中实现。

核心的内容匹配策略包括：

**年龄组匹配**：根据不同年龄段对图书出版年代的偏好差异,计算匹配分数。例如18岁以下青少年偏好2005年后的新书（匹配分1.0）,而55岁以上用户偏好1990年前的经典（匹配分1.0）。

**地域文化匹配**：基于用户国家与图书作者的文化关联性。英语国家用户偏好英语作者作品,欧洲用户偏好欧洲主题图书。

**图书质量匹配**：综合平均评分和评分人数,计算质量分数。公式为：

```
quality_score = (avg_rating/5.0 + min(1.0, rating_count/100)) / 2
```

最终匹配分数为三者加权和：`match_score = 0.5×年龄分 + 0.3×地域分 + 0.2×质量分`

#### 4.3.6 混合推荐策略实现

混合推荐策略组合多种算法,提供全场景覆盖。代码位于algorithms/hybrid.py。

```python
import pandas as pd
import logging

logger = logging.getLogger(__name__)

class HybridRecommendation:
    def __init__(self, shared_data_loader=None):
        self.data_loader = shared_data_loader
        self.user_cf = None
        self.item_cf = None

    def get_hybrid_user_recommendations(self, user_id, top_n=10):
        """混合用户推荐：70%协同过滤 + 30%内容推荐"""
        # 检查用户状态
        ratings_df = self.data_loader.get_ratings_data()
        users_df = self.data_loader.get_users_data()

        user_ratings = ratings_df[ratings_df['user_id'] == user_id]
        user_info = users_df[users_df['user_id'] == user_id]

        has_ratings = not user_ratings.empty
        has_features = not user_info.empty and \
                      not pd.isna(user_info.iloc[0]['age_group']) and \
                      not pd.isna(user_info.iloc[0]['country'])

        # 决策树逻辑
        if has_ratings and has_features:
            logger.info(f"用户{user_id}：混合推荐策略")

            # 70%协同过滤
            cf_recs = self.user_cf.get_recommendations(user_id, top_n=10)

            # 30%内容推荐（简化版：基于用户高分图书的同作者推荐）
            content_recs = self._get_content_recommendations(user_id, top_n=10)

            # 合并：取协同过滤前7本 + 内容推荐不重复的3本
            hybrid_recs = cf_recs[:7]
            cf_book_ids = set(r['bookId'] for r in cf_recs)
            content_additional = [r for r in content_recs if r['bookId'] not in cf_book_ids]
            hybrid_recs.extend(content_additional[:3])

            return hybrid_recs[:top_n]

        elif has_ratings:
            logger.info(f"用户{user_id}：纯协同过滤")
            return self.user_cf.get_recommendations(user_id, top_n=top_n)

        elif has_features:
            logger.info(f"用户{user_id}：纯内容推荐")
            return self._get_content_recommendations(user_id, top_n=top_n)

        else:
            logger.info(f"用户{user_id}：热门推荐（降级）")
            return self._get_popular_books(top_n)

    def _get_content_recommendations(self, user_id, top_n=10):
        """基于内容的推荐（简化实现：基于用户特征和高分图书）"""
        ratings_df = self.data_loader.get_ratings_data()
        books_df = self.data_loader.get_books_data()

        # 获取用户高分图书的作者
        user_high_rated = ratings_df[
            (ratings_df['user_id'] == user_id) &
            (ratings_df['rating'] >= 4.0)
        ]

        if user_high_rated.empty:
            return self._get_popular_books(top_n)

        # 提取喜欢的作者
        liked_books = user_high_rated.merge(books_df, on='book_id')
        favorite_authors = liked_books['author'].value_counts().head(5).index.tolist()

        # 推荐这些作者的其他高分图书
        user_rated_books = set(ratings_df[ratings_df['user_id'] == user_id]['book_id'])

        recommendations = []
        for author in favorite_authors:
            author_books = books_df[
                (books_df['author'] == author) &
                (~books_df['book_id'].isin(user_rated_books)) &
                (books_df['rating_count'] >= 5)
            ].sort_values(by='avg_rating', ascending=False).head(3)

            for _, book in author_books.iterrows():
                if len(recommendations) >= top_n:
                    break
                recommendations.append({
                    'bookId': book['book_id'],
                    'title': book['title'],
                    'author': book['author'],
                    'matchScore': 0.85,
                    'algorithm': 'content_based'
                })

        return recommendations[:top_n]

    def _get_popular_books(self, top_n=10):
        """热门图书推荐（降级方案）"""
        books_df = self.data_loader.get_books_data()

        popular = books_df[
            (books_df['rating_count'] >= 100) &
            (books_df['avg_rating'] >= 4.0)
        ].sort_values(by=['avg_rating', 'rating_count'], ascending=False)

        recommendations = []
        for _, book in popular.head(top_n).iterrows():
            recommendations.append({
                'bookId': book['book_id'],
                'title': book['title'],
                'author': book['author'],
                'avgRating': float(book['avg_rating']),
                'algorithm': 'popular_fallback'
            })

        return recommendations
```

混合推荐的核心是根据用户状态（是否有评分、是否有特征信息）动态选择算法组合,实现全场景覆盖。

#### 4.4.2 推荐服务调用实现

RecommendationService封装对Python算法服务的HTTP调用:

```java
@Service
@RequiredArgsConstructor
public class RecommendationService {

    private final RestTemplate restTemplate;

    @Value("${algorithm.service.url}")
    private String algorithmServiceUrl;

    public List<Map<String, Object>> getUserBasedRecommendations(Integer userId, Integer topN) {
        String url = algorithmServiceUrl + "/api/recommend/user-based";

        Map<String, Object> requestBody = new HashMap<>();
        requestBody.put("user_id", userId);
        requestBody.put("top_n", topN);

        try {
            ResponseEntity<Map> response = restTemplate.postForEntity(
                url, requestBody, Map.class
            );

            if (response.getStatusCode() == HttpStatus.OK) {
                Map<String, Object> body = response.getBody();
                if (body != null && (Boolean) body.get("success")) {
                    Map<String, Object> data = (Map<String, Object>) body.get("data");
                    return (List<Map<String, Object>>) data.get("recommendations");
                }
            }
        } catch (Exception e) {
            logger.error("调用推荐算法服务失败: {}", e.getMessage());
            return getPopularBooks(topN);  // 降级
        }

        return new ArrayList<>();
    }

    private List<Map<String, Object>> getPopularBooks(Integer topN) {
        // 从数据库查询热门图书作为降级方案
        List<Book> popularBooks = bookMapper.selectPopularBooks(topN);

        return popularBooks.stream()
            .map(book -> {
                Map<String, Object> map = new HashMap<>();
                map.put("bookId", book.getBookId());
                map.put("title", book.getTitle());
                map.put("author", book.getAuthor());
                map.put("avgRating", book.getAvgRating());
                return map;
            })
            .collect(Collectors.toList());
    }
}
```

```javascript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  const userId = ref(null)
  const username = ref('')
  const token = ref('')
  const userInfo = ref(null)

  const isLoggedIn = computed(() => !!token.value)

  function login(loginData) {
    userId.value = loginData.user.userId
    username.value = loginData.user.username
    token.value = loginData.token
    userInfo.value = loginData.user

    // 持久化到localStorage
    localStorage.setItem('userId', userId.value)
    localStorage.setItem('username', username.value)
    localStorage.setItem('token', token.value)
  }

  function logout() {
    userId.value = null
    username.value = ''
    token.value = ''
    userInfo.value = null

    localStorage.removeItem('userId')
    localStorage.removeItem('username')
    localStorage.removeItem('token')
  }

  function restoreFromLocalStorage() {
    const storedToken = localStorage.getItem('token')
    if (storedToken) {
      userId.value = localStorage.getItem('userId')
      username.value = localStorage.getItem('username')
      token.value = storedToken
    }
  }

  return {
    userId,
    username,
    token,
    userInfo,
    isLoggedIn,
    login,
    logout,
    restoreFromLocalStorage
  }
})
```

```javascript
  config => {

      config.headers['Authorization'] = `Bearer ${userStore.token}`
    }
    return config
  },
  error => {

  }
)

// 响应拦截器：处理错误和Token过期
request.interceptors.response.use(
  response => {
    const res = response.data

    if (res.code !== 200) {

        const userStore = useUserStore()
        userStore.logout()
        router.push('/login')
      }

      return Promise.reject(new Error(res.message || '请求失败'))
    }

    return res
  },
  error => {

  }
```
