## 已识别的高优先级问题

1. 论文多处将推荐策略写成固定 `7:3`，而当前实现已改为动态比例。
2. 论文多处将内容推荐写成“年龄+地域/国家匹配”，而当前实现已是“TF-IDF + 兴趣优先 + 年龄辅助”。
3. 多个接口路径、请求方式、功能页面描述与当前前后端代码不一致。
4. 论文存在 Redis、A/B 测试、CTR/CVR、严格 CORS 等未落地内容。
5. 论文对兴趣主题能力的描述强于当前实际代码，需要谨慎收敛表述。

## 当前核实基线（2026-03-07）

- 用户推荐主链路已核实为：前端 `Recommendations.vue` -> 后端 `/api/recommendations/user-based` -> 算法服务 `/api/recommend/user-based`。算法服务实际返回的是“动态比例混合推荐 + 分页缓存”，不是固定 `7:3`。
- 图书详情相似推荐链路已核实为：前端图书详情 -> 后端 `/api/books/{bookId}/similar` -> 算法服务 `/api/recommend/similar-items`。当前实现按图书数据质量动态混合物品协同过滤与内容特征，相似推荐也不应写成固定 `7:3`。
- 内容推荐实际实现已核实为两类：有评分历史时使用 `title + author + publisher` 的 TF-IDF 内容向量；无评分历史时按“兴趣优先、年龄辅助、热门兜底”生成推荐。当前算法实现中没有可落地的“地域/国家匹配推荐”主链路。
- 用户资料完善实际主流程已核实为“注册后自动登录 -> 年龄填写 -> 兴趣选择”。兴趣主题通过 `/themes` 获取、通过 `/users/{userId}/interests` 保存，论文对用户特征采集的描述应以此为准。
- `ALGORITHM_IMPLEMENTATION.md`、`docs/算法介绍文档.md`、`docs/毕业论文_*` 中均存在不同程度的过时表述；后续修订必须以当前代码与接口为准，不能直接复用这些文档中的参数、接口名和实验口径。
- 第5章实验部分需单独谨慎核对。现有评估脚本与评估报告可作为线索，但不能在未复核代码路径前直接搬入论文正文。
